# BlackPy 구현 구조

BlackPy는 프로젝트의 고정된 실행본과 그 실행에서 발생하는 입력·행동·장면·출력을 하나의 생명주기로 관리한다.

## 목차

- 전체 구조
- 구성 요소의 책임
- 설치와 편집기 연결
- 실행본과 코드 연결
- 이벤트와 동시 실행
- 시간과 움직임
- 물리 세계와 상태 동기화
- 입력과 접촉
- 텍스트 입력 대기
- 상태·종료·실행 경계

## 전체 구조

로컬 실행부가 프로젝트 설정과 등록된 스크립트의 바이트를 읽어 별도 Python 프로세스에 전달한다. Python 실행기는 스크립트마다 객체를 만들고 상태와 동작을 연결한다. 웹 입력은 로컬 실행부를 거쳐 Python으로 전달된다. C# 실행부는 Python의 표현 상태와 독립 시뮬레이션의 위치·방향을 결합한 장면을 WebSocket으로 전달한다.

학생 명령·이벤트·대기의 주체는 Python 실행기이고, 등록된 이동·회전과 물리·접촉 계산의 주체는 C# 실행부이다. Python은 실행부의 결과를 객체 상태에 반영한 뒤 학생 코드와 이벤트에 사용한다. C# 실행부는 Python 요청 횟수와 별개의 시계로 시뮬레이션과 장면을 진행하고 프로세스 수명과 전달 경계도 관리한다. 웹은 받은 상태를 그리는 책임을 가진다.

배경의 캐릭터 전용 함수는 `ScriptObject`의 진입점에서 바로 반환한다. 비동기 이동 함수도 값을 검증하거나 애니메이션을 등록하기 전에 끝나며 일반·유지 이벤트에 같은 규칙을 적용한다. 배경 접촉 이벤트는 등록 단계에서 제외한다. 캐릭터 상태 프로퍼티의 접근 검증과 공통 함수의 동작은 유지한다. 웹은 실행 객체를 선택하지 않으며 공통 명령 목록, 캐릭터 전용 표시와 캐릭터별 위치를 제공한다.

말하기는 전달된 값을 문자열로 변환하여 공백으로 연결한다. 시간 인자의 기본값은 1초이다. 시간이 None이거나 내용이 비어 있으면 즉시 표시·삭제하고 반환한다. 시작과 일반 이벤트에서는 기존 시뮬레이션 타이머를 기다리는 코루틴을 반환하고 코드 호출기가 이를 기다린다. 파일 초기화와 유지 이벤트에서는 기다리지 않고 객체에 삭제 시각만 기록한다. 실행 루프는 타이머를 처리한 뒤 경과한 삭제 시각의 메시지를 지우며, 삭제 시각이 남아 있으면 다른 이벤트가 없어도 실행을 끝내지 않는다. 각 객체는 메시지 변경 번호를 증가시켜 이전 호출의 타이머가 새 메시지를 지우지 못하게 한다. 실행 종료 시 일반 이벤트 작업과 함께 취소되므로 이전 실행의 타이머가 다음 실행에 남지 않는다.

## 설치와 편집기 연결

설치형 패키지는 Windows x64 실행부·웹·Python 지원 모듈·라이선스와 새 프로젝트 원본을 보유한다. 학생 파일은 패키지 설치 위치 밖의 프로젝트 폴더에 생성하며, 기존 파일이 있는 폴더에 새 프로젝트를 만들지 않는다. 패키지 제거와 재설치는 학생 폴더의 수명과 분리된다. 빌드는 별도의 새 배포 폴더와 기본 프로젝트 원본에서 패키지를 만들고 학생이 수정한 배포본을 입력으로 사용하지 않는다.

설치형 명령은 자기 Python 경로를 실행부에 전달하고 별도 콘솔 창 없이 실행부를 시작한다. 프로젝트의 절대경로를 명시하므로 명령을 호출한 작업 폴더나 패키지 설치 위치에 프로젝트 선택이 묶이지 않는다. 명령은 실행부의 종료를 기다리며, 마지막 브라우저 연결에 대한 수명 규칙은 폴더 배포본과 같다.

설치형의 직접 실행 연결은 Python이 `.py` 파일 자체를 실행하기 전에 그 파일 바로 옆의 프로젝트 설정을 확인한다. 배경 파일과 캐릭터 목록을 가진 BlackPy 형식이면 선택한 파일의 내용을 일반 Python으로 실행하지 않고 프로젝트 전체를 연다. 선택한 파일이 설정에 등록되어 있는지는 진입점 선택 조건이 아니며, 실제 학생 실행 대상은 항상 프로젝트 설정으로 정한다. 학생 파일·편집기 설정·코드의 줄 위치는 바꾸지 않는다.

직접 실행 연결은 설치된 Python 환경의 책임이다. 해당 환경에서 BlackPy를 제거하면 일반 Python의 파일 실행으로 돌아간다. 다른 프로젝트와 모듈·명령 문자열·대화형 실행은 가로채지 않으며 하위 폴더로 설정을 상속하지 않는다. 읽을 수 없거나 BlackPy 형식이 아닌 설정은 직접 실행 대상으로 판단하지 않는다. 내부 Python 실행기에서도 설치형 패키지가 학생 API 모듈보다 먼저 로드되어서는 안 되며, 무대를 다시 여는 재귀 실행이 발생해서는 안 된다.

샘플 진입점은 자신을 실행한 Python 환경에 설치된 BlackPy로 실행을 위임한다. 설치가 없으면 실행을 시작하지 않고 설치 방법을 안내한다. 프로젝트와 작업 폴더에 있는 동명 모듈이나 개발용 실행부로 설치 요구를 대체하지 않는다. 샘플의 학생 파일은 설치된 실행부와 별도로 유지되며, 샘플 진입점도 실행부가 끝날 때까지 기다린다.

편집기용 타입 정의는 프로젝트에 암시적으로 제공하는 이름을 알려 주며 런타임에는 실행되지 않는다. 추가 작업은 학생 코드나 편집기 설정을 고치지 않으며, 기존 안내 파일의 내용이 다르면 교체를 거절한다. 이 정의는 일반 함수 호출과 상태 조회를 설명하는 수단이며, 코드 변환이나 이벤트 동시 실행을 편집기에서 재현하지 않는다. 배경의 움직임 금지 등 실행 대상의 제약은 런타임이 검사한다.

pip 설치형은 같은 타입 정의를 패키지의 `_editor` 디렉터리에도 포함하고 `.pth`의 정적 상대경로로 Python 검색 경로에 추가한다. 분석기는 선택한 Python 환경에서 이 정의를 찾으므로 프로젝트 폴더 없이 연 파일에도 명령 안내를 제공한다. 디렉터리에는 `.pyi`만 두어 Python 실행용 모듈을 추가하거나 실제 내장 함수를 바꾸지 않는다. 기존 프로젝트·사용자 정의 안내는 우선하며 일반 이름·타입 오류 진단은 유지한다. 패키지를 제거하면 이 환경 안내와 검색 경로도 제거된다.

## 실행본과 코드 연결

새 프로젝트 설정은 `_blackpy/project.json`에 두며 배경과 캐릭터를 명시적으로 등록한다. 기존 프로젝트의 바깥에 있는 `project.json`도 계속 읽으며 파일을 자동 이동하지 않는다. 각 객체는 고유한 이름과 프로젝트 바로 아래의 서로 다른 Python 파일을 가진다. 파일 이름은 Windows의 대소문자 비구분을 고려하여 중복을 검사하며, 외부 경로와 연결 파일은 실행본에 포함하지 않는다.

시작할 때 설정을 한 번 읽고 등록된 파일 전체의 바이트를 고정한다. 모든 스크립트를 구문 분석한 뒤 초기 설정과 이벤트를 준비하고, 준비가 끝나면 시작 이벤트를 실행한다. 초기화 구간에는 상태·절대 설정과 출력을 허용하며, 갱신 루프를 기다리는 이동·회전·대기는 오류로 거절한다. 실행 중 저장한 코드·설정은 현재 실행에 섞이지 않는다. 추가로 import하는 모듈은 고정 범위 밖이다.

일반 def와 호출은 내부의 협력 실행 코드로 변환된다. 상태 이름의 읽기·대입은 해당 파일 객체의 속성과 연결되며, 별도 self나 global이 필요하지 않다. 원래 파일 경로와 줄 번호, 실행에 사용한 소스는 보존하여 오류에 사용한다. 학생 코드에 클래스·명시적 async/await·yield를 쓰는 방식은 지원하지 않는다.

배경·캐릭터의 선택 항목 `image`는 `project.json`과 같은 폴더의 그림 파일 이름이다. 프로젝트 로더는 설정을 읽을 때 이름·확장자·존재·크기와 연결 파일 여부를 검사하며, 그림은 Python 실행본에 포함하지 않는다. 웹은 프로젝트 정보를 받은 뒤 토큰을 붙여 `/api/image`로 그림을 요청하고 객체 URL로 디코딩한다. 실행부는 현재 고정 설정이나 실행 전 설정에 적힌 이름만 제공하며 응답에 sandbox 콘텐츠 보안 정책을 붙인다. 렌더러는 장면의 배경 모양이 설정의 `kind`와 같을 때 배경 그림을, 캐릭터 식별자가 설정 순서와 맞는 캐릭터에 캐릭터 그림을 기본 모양 대신 그린다. 크기와 판정은 `kind`의 상자를 유지한다.

실행에 필요한 내부 모듈은 학생 파일을 모듈로 탐색하기 전에 준비한다. 학생 파일 이름이 내부 의존성과 겹쳐도 실행기를 대신하지 않으며, 준비 이후에는 학생이 같은 폴더의 보조 모듈을 가져올 수 있다.

## 이벤트와 동시 실행

키·클릭·방송의 일반 이벤트는 같은 호출이 진행 중이면 같은 재입력을 무시한다. 객체와 이벤트 종류를 기준으로 구분하고, 키 입력과 방송은 키 이름·신호 이름까지 구분한다. 다른 키나 다른 신호는 병행할 수 있다. 접촉 시작·종료는 이 재입력 제한의 예외이며 C#에 기록된 각 전환을 독립 호출로 전달한다. 이전 접촉 호출이 기다리는 중에도 다음 전환을 호출하며, 각 호출 안의 명령 순서와 전체 활성 호출 수 제한은 유지한다.

유지 이벤트는 키 유지·자신 클릭 유지·접촉 유지의 세 종류이다. Python이 응답을 처리할 때 최신 시뮬레이션 갱신마다 한 번 호출하며 이전 호출이 끝나기를 기다리지 않는다. 처리하지 못한 갱신의 유지 호출을 뒤늦게 재생하지 않는다. 종료 이벤트의 명령에는 일반 이벤트의 이동·대기 규칙을 적용한다. 상태가 해제되면 새 유지 호출과 등록된 유지 이동을 멈추고 기존 함수 호출은 완료한다.

한 호출의 명령은 완료 순서를 유지한다. 보조 함수를 호출하면 호출한 이벤트의 일반·유지 문맥을 이어받는다. 방송 수신은 별도의 일반 이벤트 문맥에서 실행되며 송신자는 수신 함수의 완료를 기다리지 않는다.

실행기 자체는 하나의 asyncio 루프에서 학생 실행을 조율한다. 함수 진입과 for·while 반복에는 실행을 양보하는 지점을 둔다. Python 외부 함수의 긴 동기 작업까지 비동기로 바꾸는 것은 아니다. 브라우저 제어와 프로세스 종료는 별도 실행부에서 처리한다.

동시에 활성화된 호출은 실행 전체에서 최대 4,096개이다. 초과하면 호출을 조용히 생략하지 않고 한국어 오류로 실행을 종료한다. 특히 유지 이벤트에 긴 대기나 끝나지 않는 반복을 넣으면 호출이 누적될 수 있다.

## 시간과 움직임

C# 시뮬레이션과 실행 중 장면 발행은 독립된 단조 시계로 최대 초당 60회 갱신한다. Python의 요청이 많아도 시뮬레이션 시간이 더 빨리 흐르거나 장면 발행 상한이 높아지지 않는다. 웹의 화면 그리기 횟수와 물리의 내부 계산 간격은 이 외부 갱신 횟수와 별개이다.

Python의 상태 교환은 자체 최대 60Hz로 명령을 제출하고 최신 결과를 받는 주기이다. Python의 처리가 느려지거나 잠시 멈춰도 이미 등록한 이동·회전·유지 이동과 물리는 C#에서 계속 진행한다. 다음 교환에는 최신 결과를 적용하며 놓친 Python 갱신을 연속 재생하지 않는다.

C# 실행부는 요청과 갱신을 한 소유자에서 처리한다. 요청은 다음 시각을 기다리는 실행부를 깨울 수 있지만, 시뮬레이션 갱신과 장면 발행은 각 목표 시각을 따른다. 긴 지연 뒤에는 한 갱신에 반영할 경과 시간을 최대 0.1초로 제한하고 초과분을 쌓아 두지 않는다.

일반 상대 이동은 명령 시작 당시의 방향·속도 배율로 총변위·총회전과 소요 시간을 정하여 고유한 완료 식별자와 함께 등록한다. 기준 속도는 초당 200단위, 회전은 초당 180도이다. 값을 생략하면 거리는 100, 회전은 90도이다. C#이 시간에 따라 적용하고 완료를 보고하면, Python은 실행부의 위치·방향을 반영한 뒤 해당 호출의 다음 줄을 실행한다.

유지 이벤트의 이동·회전은 초당 변화량으로 등록한다. 앞으로의 값은 속도이므로 Python이 `값 × 200 × 속도 배율`의 초당 이동량으로 바꾸어 전달하며 생략하면 속도 1이다. 회전 값은 그대로 초당 각도이다. 방향을 먼저 지정하지 않은 앞으로는 forward로 전달하여 C#이 매 소구간의 실제 방향으로 변환한다. 같은 호출에서 절대 방향을 먼저 지정한 이동은 x/y로 고정한다. 시뮬레이션은 최대 1/120초 소구간으로 회전·이동을 적용한다. 키·포인터·접촉의 원인과 상태 세대별로 최신 호출의 이동을 유지한다. 새 호출은 이동량 0으로 시작하며, 한 호출 안의 명령은 합산하고 다음 호출의 값으로 교체한다. 서로 다른 원인의 이동은 합산한다. 호출 순서를 구분하여 오래된 호출이 최신 값을 덮어쓰지 못하게 한다.

키·포인터의 해제와 접촉 종료는 C#이 해당 유지 이동을 즉시 취소한다. 해제된 세대에서 늦게 도착한 이동은 적용하지 않는다. 같은 키를 다시 눌러도 새 세대이므로 이전 호출의 이동을 재사용하지 않는다. 이미 시작한 Python 함수 자체는 계속 실행할 수 있으며 일반 이벤트의 등록 이동은 이 해제로 취소되지 않는다.

같은 객체의 여러 상대 동작은 위치를 각각 덮어쓰지 않고 변화량을 더한다. 위치·방향의 절대 설정은 즉시 반영되며, 진행 중인 상대 동작의 남은 변화량은 이후에도 계속 더해진다. 따라서 절대 설정은 다른 호출의 이동을 취소하는 명령이 아니다.

'물리' 모드에서는 상대 이동의 요청 변위를 엔진의 형상 이동 검사로 제한하여 벽을 통과하지 않게 한다. 중력·충격에 의한 움직임은 명령 이동과 함께 적용한다. 이동의 대기 시간은 원래 명령 기준으로 끝나므로 장애물에 막혔다고 호출이 계속 남지 않는다. 대기 완료 뒤 이어지는 코드는 물리 결과가 반영된 상태를 보아야 한다.

## 물리 세계와 상태 동기화

물리 계산은 Box2D.NET으로 수행하며 학생 Python 환경에 물리 라이브러리를 요구하지 않는다. 물리 세계는 실행 하나에 속하고 새 실행을 시작할 때 새로 준비한다. 중지·오류·완료·재시작은 이전 세계와 대기 중인 물리 명령을 함께 정리하며 이전 실행의 결과를 새 객체에 적용하지 않는다.

Python은 객체별 모드·무게·크기·가시성과 순서가 있는 이동·절대 배치·충격·정지 명령을 전달한다. C#은 입력을 검증하고 적용하여 위치와 접촉 식별자를 반환한다. 물리 시간은 C# 시뮬레이션이 소유하며 상태 교환 요청이 직접 진행시키지 않는다. 엔진은 1/120초의 고정 간격과 각 간격의 내부 분할 4회로 계산한다. 외부 갱신의 0.1초 예산은 최대 12회의 고정 간격 계산에 해당한다. 응답을 기다리는 동안 발생한 새 학생 명령이나 절대 배치를 이전 응답이 덮어쓰지 않아야 한다.

'없음'은 충돌과 물리에서 제외한다. 기본값인 '충돌만'은 명령으로 움직이는 운동학적 물체이며 힘·중력에 반응하지 않고 다른 고체와 경계에 막힌다. 트리거는 기본 false이며 어느 한쪽이 true이면 차단·충격 응답을 생략하고 접촉을 유지한다. '물리'는 중력·무게·충격과 충돌 응답을 사용하는 동적 물체이다. 충격은 한 번만 적용하며 정지는 현재 물리 속도만 지운다. 모드가 달라지면 이전 속도를 지우고, 숨긴 물체는 물리와 접촉에서 제외하며 다시 보일 때 속도 0으로 재개한다.

물리 세계의 기준은 무대 100단위가 1m, 중력이 `(0, -9.8)`m/s²이다. 800×600 무대의 사방에 고정 벽을 두며 동적 물체가 밖으로 나가지 않게 한다. 절대 배치는 중간 장애물을 통과할 수 있으나 동적 물체의 사각 범위는 경계 안으로 제한한다. 동적 물체의 크기는 무대를 넘을 수 없다. 크기 변경은 형상을 갱신하면서 설정한 무게를 유지한다.

충돌 형상은 방향을 반영하는 사각형이다. 엔진의 자동 각운동은 잠그고 명령 회전만 Box2D transform에 반영한다. 고체의 명령 이동은 shape cast로 차단한다. 명령 회전은 최대 2도·모서리 이동 1단위 이하로 나누고 Box2D TOI와 침투 깊이 검사로 벽 통과를 막는다. 이미 닿은 상태에서 멀어지는 회전은 허용한다. 절대 방향·좌표 설정은 경로 검사를 하지 않는 배치 명령이다. 충돌 감지와 응답은 엔진 기능을 사용하며 별도의 Python 물리 계산을 중복 구현하지 않는다.

모양 뒤집기는 무대 축에 대한 거울 반사이다. 가로는 방향 θ를 `180 - θ`로, 세로는 `-θ`로 바꾸고, 그림을 진행 방향 축에 대해 한 번 더 뒤집어야 하므로 Python 객체가 보유하는 반사 불리언 상태를 반전한다. 방향 변경은 방향 대입과 같은 경로로 처리하여 독립 시뮬레이션에 heading 명령을 보내며, 유지 호출 안에서는 이후 앞으로를 고정 방향 이동으로 등록한다. 장면에는 반사 상태를 `flipVertical`로, `flipHorizontal`은 false로 전달한다. 두 필드는 회전한 그림 좌표계의 축이며 실행부의 장면 복사·독립 갱신에서도 유지한다. 두 필드를 보내지 않은 장면은 false로 처리한다. 웹은 기존 방향으로 회전한 뒤 그림의 축에 음수 배율을 적용하며 이름표·말풍선에는 이 변환을 적용하지 않는다.

## 입력과 접촉

키의 눌림·해제는 상태 전환으로 처리하고 브라우저의 자동 반복 입력은 별도 누름으로 처리하지 않는다. Python이 최신 갱신을 처리할 때 현재 누른 각 키의 유지 이벤트를 호출한다. 입력 전환 기록은 Python의 수신 확인까지 보관하여 교환이 늦어져도 누름·해제 순서를 보존한다.

자신 클릭은 마우스 왼쪽 버튼을 누른 순간의 위치로 대상을 정한다. 가장 앞에 있는 보이는 캐릭터를 고르고, 없으면 배경을 선택한다. 포인터가 움직여도 버튼 해제까지 대상을 고정한다. 초점 상실·연결 변화는 누른 키와 버튼을 해제한다.

접촉은 보이는 객체 중 '없음'이 아닌 객체의 사각 범위로 판단한다. 경계에 닿은 상태도 접촉에 포함하며 '충돌만' 객체끼리도 접촉을 조회할 수 있어야 한다. C#이 이전·현재 접촉 집합의 차이로 진입·종료를 기록하고 Python의 수신 확인까지 보관한다. 전환의 순서 번호와 수신 확인으로 중복 전달을 막는다. Python이 멈춘 사이 접촉이 여러 번 시작하고 끝나도 각 전환의 호출을 순서대로 시작하며, 유지 이벤트는 최신 접촉 목록을 사용한다. 내부 식별자는 이름을 바꾸어도 유지한다. 이름 목록은 프로젝트 등록 순서로 현재 이름을 담고 빈 목록은 이벤트로 호출하지 않는다. 무대 경계 벽은 학생 객체 이름 목록에서 제외한다. 닿은 객체 목록의 조회는 복사본을 반환하여 학생의 목록 변경이 물리 상태를 바꾸지 않게 한다.

## 텍스트 입력 대기

학생 스크립트의 input은 해당 객체에 연결된 협력 대기로 실행한다. Python 런타임이 실행 내에서 증가하는 질문 식별자와 요청 순서를 소유하며, 가장 앞의 질문 하나만 장면에 포함한다. 답은 문자열 그대로 반환하며, 질문을 기다리는 호출 외의 이벤트와 시간 진행을 유지한다. 초기화 중에도 장면과 답 전달을 유지하되 시작·조작 이벤트는 전체 초기화 뒤에 실행한다. 유지 이벤트에서 질문하는 호출은 명확한 오류로 끝내어 매 프레임 질문이 누적되지 않게 한다.

로컬 실행부는 답의 실행 식별자·현재 질문 식별자·길이·한 줄 형식을 검사한다. 같은 질문에 대한 첫 답만 접수하고, 이미 답한 질문은 늦게 도착한 장면에 있더라도 다시 표시하지 않는다. 입력 초점 초기화는 조작 상태를 해제하되 접수된 답을 버리지 않는다. 장면과 질문은 복사하여 보관하고, 중지·재시작·오류·완료 때 남은 질문과 답 대기열을 정리한다.

웹은 콘솔의 출력 다음에 질문과 답 입력칸을 이어서 표시한다. 객체 이름으로 질문자를 별도 표시하지 않으며 첫 표시 때 입력 초점과 콘솔 스크롤을 옮긴다. Python 런타임은 유효한 답을 접수하면 질문과 답을 표준출력에 한 번 남긴 뒤 대기 호출을 재개하여 후속 출력과의 순서를 유지한다. 이 출력은 기존 콘솔 출력의 길이·보관 개수 제한을 따른다.

프레임 갱신은 작성 중인 답이나 초점을 덮어쓰지 않는다. 한글 조합 중 Enter를 제출로 처리하지 않으며, 전송 중 중복 제출을 막고 통신 오류에는 입력값을 유지하여 재시도할 수 있게 한다. 연결 해제나 실행 변경 시 입력칸을 비우며 브라우저 저장소에 답을 기록하지 않는다.

## 상태·종료·실행 경계

각 실행은 새 식별자를 갖는다. 이전 실행의 입력·장면·조회 요청은 현재 실행에 적용하지 않는다. 중지·오류·완료·재시작은 시뮬레이션 시계와 등록 동작·유지 세대·완료 및 전환 기록을 함께 정리한다. 실행 중 중복 시작은 거절하며, 재시작은 기존 프로세스와 자식을 정리한 뒤 새 실행본을 읽는다.

시작 이벤트만 있고 물리 모드 객체가 없는 프로젝트는 모든 호출이 끝나면 완료된다. 다른 이벤트가 등록되었거나 물리 모드 객체가 있는 프로젝트는 입력과 물리 갱신을 계속한다. 처리되지 않은 오류는 실행 전체를 끝내며, 중지·완료 뒤 마지막 장면과 콘솔은 남는다. 마지막 웹 연결을 닫으면 학생 실행과 자식 프로세스를 중지하고 3초 뒤 로컬 실행부도 종료한다.

연결이 남아 있거나 유예 시간 안에 다시 연결되면 실행부 종료를 취소한다. 새로고침은 실행부와 마지막 장면을 유지하지만 학생 실행은 중지된 상태이다. 자동으로 브라우저를 여는 실행은 첫 연결을 최대 60초 기다린다. 직접 연결하는 `--no-browser` 실행은 첫 연결 제한 없이 기다리고, 한 번 연결된 뒤에는 같은 종료 규칙을 적용한다. 브라우저 열기 자체가 실패하면 실행부도 오류로 종료한다.

폴더 배포본의 기본 진입점은 콘솔을 할당하지 않는 Windows GUI 실행 파일이다. 관리 코드와 동봉 런타임은 공통 실행부 폴더에 두며, 진입점이 자기 위치 기준 상대경로로 불러온다. 프로젝트는 진입점과 같은 폴더에서 찾고 명시적인 `--project`가 있으면 그 경로를 우선한다. 학생에게 콘솔을 닫는 별도 종료 절차를 요구하지 않는다.

입력 대기열과 장면 데이터에는 상한이 있다. 연속 포인터 이동은 합치되 누름·해제 순서를 보존하며, 입력 초기화는 대기열이 찼을 때도 처리한다. 장면은 검증 후 복사된 상태로 보관한다.

서비스는 로컬 주소에서만 열고 API·WebSocket에 연결 토큰을 요구한다. Origin과 Host를 검사한다. 이는 실행 경계이며 Python 코드를 격리하는 보안 샌드박스는 아니다. 별도 사용자 코드의 파일·네트워크 접근은 일반 사용자 권한으로 실행된다.
