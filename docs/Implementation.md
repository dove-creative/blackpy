# BlackPy 구현 구조

BlackPy의 실행부는 한 번의 Python 실행과 그 실행에서 발생한 움직임·출력·종료를 같은 생명주기로 관리한다.

## 목차

- 전체 구조
- 구성 요소의 책임
- 대표 실행 흐름
- 상태와 종료
- 실행 경계

## 전체 구조

학생 파일은 별도의 Python 프로세스에서 실행한다. Python 지원 모듈은 로컬 HTTP로 명령이나 장면을 전달하고, 실행부는 현재 실행에 속한 요청인지 검사한다. 웹은 WebSocket으로 상태를 받아 장면과 출력을 표시한다.

실행부는 로컬 주소에서만 서비스를 제공한다. 실행 상태와 움직임 처리는 전용 루프에서 관리하며, 웹 연결과 Python 프로세스의 수명을 실행 상태에 연결한다.

## 구성 요소의 책임

| 구성 요소 | 보유 정보 | 제공 책임 |
| --- | --- | --- |
| 실행 세션 | 실행 식별자, Python 프로세스, 출력, 연결 상태 | 실행 시작·중지·재시작, 오류 수집, 프로세스 정리 |
| 기본 이동 처리 | 위치, 방향, 진행 중인 이동 | UniEngine의 이동 기능을 사용한 순차 이동·회전 |
| 놀이 장면 처리 | 배경, 캐릭터 목록, 안내 문구 | 장면 검증, 현재 상태 보관, 웹 전달 |
| Python 지원 모듈 | 연결 정보, 캐릭터 상태, 동작 진행률 | 학생 명령 표현, 완료 대기, 준비된 동시 움직임 |
| 웹 무대 | 수신한 장면과 실행 상태 | 그림·출력·오류 표시, 실행 제어 요청 |

Python 놀이 명령의 보간은 단조 시계를 기준으로 계산하고 초당 약 30회 장면을 전달한다. 실행부는 수신한 장면을 검증한 뒤 복사된 상태를 공유한다. 기본 고양이 이동은 별도의 UniEngine 이동 경로를 유지한다.

## 대표 실행 흐름

1. 실행기는 대상 예제 폴더를 정하고 로컬 실행부를 연다.
2. 웹의 시작 요청을 받으면 장면과 출력을 초기화하고 새 실행 식별자를 만든다.
3. 저장된 `main.py`를 새 Python 프로세스에서 실행한다.
4. Python 명령은 현재 실행에 속한 요청으로 처리하며, 이동은 완료 뒤 다음 명령으로 진행한다.
5. 웹은 위치·방향·장면·출력을 받아 현재 결과를 표시한다.
6. 완료·오류·중지는 실행 자원을 정리하고 마지막 결과를 남긴다.

새 실행이 시작된 뒤 이전 실행의 명령이나 장면은 적용하지 않는다. 실행 중 중복 시작을 거절하며, 재시작은 진행 중인 실행을 정리한 다음 새로운 실행으로 전환한다.

## 상태와 종료

중지는 진행 중인 이동을 취소하고 Python 프로세스 트리를 종료한다. Python 부모가 먼저 종료해도 남은 자식 프로세스를 정리한다. 실행부가 종료될 때도 해당 실행에서 만든 프로세스가 남지 않도록 수명을 연결한다.

웹 연결이 여러 개일 때는 마지막 연결이 끊기면 실행을 중지한다. 다시 연결한 웹에는 현재 상태를 전달한다. 이 복원은 실행부가 보유한 상태에 따른 것이며 브라우저 저장소에 의존하지 않는다.

출력과 오류는 최근 1,000줄까지 보관한다. 한 줄이 2,048자를 넘으면 나누어 수집한다. Python 오류에는 학생 파일과 줄 정보를 유지한다. 표준입력은 닫힌 상태로 실행한다.

## 실행 경계

API 요청은 연결 토큰을 요구하고 Origin과 Host를 검사한다. 실행 대상은 지정한 폴더의 `main.py`로 한정하며, 명령과 장면에는 현재 실행 식별자가 필요하다. 값의 범위와 장면 크기를 검사한 뒤 상태에 반영한다.

학생 Python은 일반 사용자 권한으로 실행된다. 이 구조는 웹 연결과 실행 생명주기를 관리하기 위한 것으로, 임의 Python 코드의 파일·네트워크 접근을 격리하는 보안 샌드박스는 아니다.

검증 항목과 실행 절차는 [Testing](Testing.md), 실제 수행한 결과는 해당 문서에서 연결하는 검증 기록에 둔다.
