# BlackPy 사용 안내

이 문서는 학생의 실행 흐름과 교사의 프로젝트 준비, 한글 Python API를 설명한다.

## 목차

- 학생 실행
- pip 설치와 새 프로젝트
- VS Code 명령 안내
- 공통 명령 팔레트와 파일
- 기본 프로젝트
- 이벤트
- 이동과 상태
- 물리와 충돌
- 표현·계산·조회
- 텍스트 입력
- 교사 프로젝트 설정
- 배포와 이전 형식
- 오류와 실행 제약

## 학생 실행

1. Windows x64 컴퓨터에 Python 3.10 이상과 VS Code 등 편집기를 준비한다.
2. pip 설치형은 `blackpy run 내프로젝트`, 폴더 배포본은 실습 폴더의 `_blackpy/시작.exe`로 연다.
3. 웹에 표시된 대상 파일을 편집기에 열어 코드를 수정하고 저장한다.
4. 웹에서 시작을 누르고 무대를 클릭해 입력 초점을 옮긴다.
5. 저장한 변경을 적용하려면 다시 시작을 누른다. 중지는 현재 실행 전체를 멈춘다.

`시작.exe`는 콘솔 창 없이 기본 웹 브라우저를 연다. BlackPy를 연 마지막 탭이나 창을 닫으면 현재 Python 실행을 중지하고 약 3초 뒤 실행부도 종료된다. 같은 실행을 연 다른 탭이 있으면 계속 유지된다. 새로고침으로 3초 안에 다시 연결되면 실행부를 유지하며, 멈춘 코드는 시작 버튼으로 다시 실행한다.

브라우저가 처음 연결되기 전에 닫혔거나 열리지 않은 경우를 위해 첫 연결은 최대 60초 기다린다. 실행 준비 오류는 안내 창으로 표시한다. 자세한 오류 확인이 필요하면 같은 폴더의 `Debug.bat`으로 콘솔을 열 수 있다.

0.1.1 설치형은 VS Code의 'Run Python File' 버튼으로 학생 파일을 실행하여 웹 무대를 열 수 있다. 열린 무대의 시작·중지·다시 시작 버튼으로 학생 코드의 실행을 제어한다. BlackPy 외의 Python 실행 의존성은 없다.

## pip 설치와 새 프로젝트

설치형은 Windows x64의 Python 3.10 이상 환경에서 [PyPI](https://pypi.org/project/blackpy/)의 `blackpy` 패키지를 설치한다.

```powershell
python -m pip install blackpy
blackpy new 내프로젝트
blackpy run 내프로젝트
```

이미 설치했다면 같은 Python 환경에서 다음 명령으로 갱신한다.

```powershell
python -m pip install --upgrade blackpy
```

`new`는 없거나 비어 있는 폴더에 기본 프로젝트를 만든다. 기존 파일이 있으면 생성을 거절하며 학생 코드를 덮어쓰지 않는다. `run`은 폴더의 `_blackpy/project.json`을 읽고 브라우저를 연다. 폴더를 생략하면 현재 폴더를 사용한다. 실행부의 별도 콘솔 창은 열지 않으며, 명령을 입력한 터미널은 마지막 브라우저 연결 종료 후 실행부가 끝날 때까지 기다린다.

```text
내프로젝트/
├─ 배경.py
├─ 고양이.py
├─ 자동차.py
└─ _blackpy/
   ├─ project.json
   └─ __builtins__.pyi
```

공통 실행부·웹·Python 지원 모듈은 설치한 Python 환경의 `blackpy` 패키지에 들어간다. 학생 폴더에는 `_runtime`이나 실행 파일이 필요하지 않다. 학생 폴더는 설치 환경 밖에 있으므로 패키지 재설치·제거와 별도로 유지된다. `run`은 BlackPy 명령을 실행한 Python을 학생 실행에도 사용한다.

`blackpy`를 찾지 못하면 같은 Python으로 `python -m blackpy new 내프로젝트`, `python -m blackpy run 내프로젝트`를 사용한다. 가상환경에 설치했다면 해당 환경을 활성화하거나 그 환경의 Python 경로를 지정한다. 실행 옵션은 `--no-browser`, `--port <번호>`이며 기본 포트 0은 자동 선택이다.

0.1.2는 이전 로컬 0.1.1 wheel과 버전을 구분한 공개본이다. 물리 명령을 찾지 못하는 이전 로컬 설치본도 위의 갱신 명령으로 교체할 수 있다. 학생 파일과 `project.json`은 그대로 유지된다.

전달받은 wheel 파일은 `python -m pip install ./blackpy-0.1.2-py3-none-win_amd64.whl`로 설치한다. 소스에서 wheel을 만드는 방법과 공개 절차는 [Development](Development.md)에 있다.

### 학생 파일에서 무대 열기

학생 파일의 직접 실행은 0.1.1부터 제공한다. 이전 버전에서는 `blackpy run`을 사용하거나 설치된 패키지를 갱신한다.

VS Code에서 개별 프로젝트 폴더를 열고 BlackPy를 설치한 Python을 선택한다. 학생 프로젝트의 `배경.py`, `고양이.py` 등 어느 `.py` 파일에서든 'Run Python File'을 누르면 해당 프로젝트의 웹 무대가 열린다. 명령줄에서도 다음과 같이 실행한다.

```powershell
python 내프로젝트/고양이.py
```

작업 폴더가 달라도 실행한 파일의 폴더를 사용한다. 파일 하나만 실행하는 것이 아니라 `project.json`에 등록된 배경·캐릭터 전체를 준비한다. 등록하지 않은 `.py` 파일에서 열어도 그 파일이 캐릭터로 추가되지는 않는다. 학생 파일에 실행용 코드나 `import`를 넣을 필요가 없다.

이 연결은 해당 Python 환경에 BlackPy가 설치되어 있을 때만 동작한다. 설치하지 않았거나 VS Code에서 다른 Python을 선택하면 일반 Python 실행이므로 무대가 열리지 않고 한글 명령에서 이름 오류가 날 수 있다. 설치 여부를 안내하는 `시작.pyw`와는 구분된다.

직접 실행은 학생 파일 옆의 `_blackpy/project.json`을 사용하며, 기존에 바깥에 둔 `project.json`도 지원한다. 하위 폴더까지 적용하지 않으며 `python -m`, `python -c`, 대화형 실행, 선택한 코드 일부 실행과 디버거 실행은 이 연결의 대상이 아니다. `-S`로 Python의 설치 초기화를 생략한 실행도 대상이 아니다. 설정 파일을 고치는 중이라 직접 실행이 연결되지 않으면 `blackpy run 프로젝트경로`로 오류를 확인한다.

### 저장소 샘플 실행

[samples](../samples/README.md)의 예제는 설치된 BlackPy로 실행한다. 저장소 루트에서 다음 명령을 사용한다.

```powershell
python -m pip install blackpy
python -m blackpy run ./samples/01-movement
```

Python의 `.pyw` 파일 연결이 설정되어 있으면 각 예제 폴더의 `시작.pyw`를 더블클릭하여 콘솔 창 없이 열 수 있다. 샘플 실행기는 자신을 실행한 Python 환경에 BlackPy가 없으면 설치 안내를 표시하고 종료한다. 패키지를 자동 설치하거나 저장소의 실행부를 대신 사용하지 않는다. `Debug.bat`은 콘솔에서 같은 실행 오류를 확인할 때 사용한다.

0.1.1 설치형에서는 예제 폴더의 `.py` 파일을 VS Code에서 실행하거나 `python ./samples/01-movement/고양이.py`로 열어도 된다. 직접 실행의 버전·Python 선택 조건은 위의 '학생 파일에서 무대 열기'와 같다.

여러 Python이나 가상환경을 사용하는 경우 설치와 실행에 같은 Python을 사용한다. 더블클릭의 Python과 터미널의 Python은 다를 수 있으므로, 가상환경에서는 해당 환경을 활성화한 터미널에서 위 명령을 실행하는 방법이 명확하다. 이전에 생성한 샘플의 `시작.exe`는 현재 샘플 진입점이 아니다.

## VS Code 명령 안내

VS Code에 Python·Pylance 확장을 준비한다. 0.1.3의 pip 설치형은 BlackPy를 설치한 Python을 선택하면 프로젝트 폴더를 열지 않고 학생 파일만 열어도 명령 안내를 제공한다. 기존 0.1.2 프로젝트의 바깥에 둔 `__builtins__.pyi`도 계속 지원한다. 새 폴더 배포본을 편집할 때도 명령 안내를 받으려면 BlackPy 0.1.3을 설치한 Python을 선택한다.

`__builtins__.pyi`는 BlackPy가 실행 시 제공하는 명령·상태의 이름과 인자를 편집기에 알리는 파일이다. 학생이 `말하기`나 `앞으로`를 사용하기 위해 `import`를 추가할 필요가 없으며, 정의되지 않은 이름의 진단도 끄지 않는다. 잘못 쓴 이름은 계속 오류로 표시된다. 이 방식은 [Pyright의 내장 이름 확장](https://github.com/microsoft/pyright/blob/main/docs/builtins.md)을 사용한다.

새 프로젝트와 새 폴더 배포본에는 안내 파일이 포함된다. 이전에 만든 프로젝트에는 다음 명령으로 추가한다.

```powershell
blackpy editor 내프로젝트
```

같은 안내 파일이 있으면 그대로 유지한다. 내용이 다른 `__builtins__.pyi`가 이미 있으면 덮어쓰지 않고 필요한 정의를 직접 합치도록 안내한다. 학생 Python 파일과 VS Code 설정은 변경하지 않는다. 프로젝트 안내 파일을 사용할 때는 저장소 전체나 여러 예제의 상위 폴더 대신 실제 편집할 프로젝트 폴더를 연다.

환경에 등록된 안내는 선택한 Python을 사용하는 일반 Python 파일에서도 BlackPy 명령을 인식하게 한다. 실행 자체는 기존과 같이 BlackPy 프로젝트에서만 한글 명령을 제공한다. 프로젝트나 Python 환경에 사용자 정의 `__builtins__.pyi`가 있으면 그 정의를 우선하며 설치·재설치가 이를 덮어쓰지 않는다. 설치 후에도 이전 경고가 남으면 VS Code 명령 팔레트에서 `Python: Restart Language Server`를 실행한다.

이 파일은 편집기용이며 실행되거나 Python의 실제 내장 함수를 바꾸지 않는다. 일반 Python 분석기가 BlackPy의 코드 변환·이벤트·배경과 캐릭터의 실행 제약까지 모두 검사하는 것은 아니므로 최종 동작과 오류는 웹 실행에서 확인한다.

예를 들어 함수 안의 `크기 += 0.1`은 BlackPy에서 객체 상태의 증감으로 처리하지만, 일반 Python 분석기는 지역 변수의 대입 전 참조로 판단하여 `reportUnboundVariable`을 표시할 수 있다. 안내 파일이 해결하는 범위는 제공 명령·상태의 이름과 타입이며 이런 구문 변환 차이는 남는다. 크기 변경은 `크기_바꾸기(0.1)` 명령으로도 작성할 수 있다.

## 공통 명령 팔레트와 파일

웹의 명령 팔레트는 배경과 캐릭터가 함께 사용한다. 객체 선택 없이 모든 분류를 볼 수 있으며 캐릭터 전용 항목에는 표시가 붙는다. 명령의 코드 행을 클릭하면 해당 코드가 복사된다. 이벤트는 def와 들여쓴 pass까지 포함한 템플릿이며, 붙여 넣은 뒤 pass를 원하는 명령으로 바꾼다.

프로퍼티 대입 예시는 웹의 명령 목록에 표시하지 않는다. `속도 = 1`, `위치 = (0, 0)`, `배경 = "city"` 등의 대입은 Python 코드에서 계속 사용할 수 있다. 상태 읽기와 함수형 변경 명령은 명령 목록에 표시한다.

실행 대상은 코드를 작성한 Python 파일로 정한다. `고양이.py`의 명령은 고양이가, `배경.py`의 명령은 배경이 실행한다. 코드는 VS Code에서 작성한다. 변수·공통 함수 생성, 캐릭터 추가·설정 편집은 웹에서 제공하지 않는다.

명령 분류는 이벤트·움직임·물리·생김새·계산·주변이다. 접촉 이벤트와 닿은 객체 목록은 물리에서 찾고, 다른 객체의 이름·위치·방향과 input은 주변에서 찾는다. 변수·함수 만들기 영역은 보류한다.

## 기본 프로젝트

```text
blackpy/
└─ 실습/
   ├─ 배경.py
   ├─ 고양이.py
   ├─ 자동차.py
   └─ _blackpy/
      ├─ project.json
      ├─ __builtins__.pyi
      ├─ 시작.exe
      ├─ Debug.bat
      └─ _runtime/
```

파일 하나가 하나의 배경 또는 캐릭터를 정의한다. 아래 코드는 고양이.py에 작성하는 예이다.

```python
def 시작():
    위치 = (-160, -80)
    말하기("방향키를 누르고 있어 보세요!")


def 키_클릭_중(누른_키):
    if 누른_키 == "오른쪽":
        방향 = 0
        앞으로(120)
    elif 누른_키 == "왼쪽":
        방향 = 180
        앞으로(120)
```

명령의 대상은 항상 이 파일의 고양이이다. class, self, async, await나 이벤트 등록 코드는 필요하지 않다. 최상위에서는 초기 상태 대입·절대 설정·출력과 함수 정의를 사용할 수 있다. 시간이 필요한 상대 이동·회전·기다리기는 이벤트 함수 안에 두며, 초기화 구간에서 호출하면 오류로 안내한다.

## 이벤트

| 함수 정의 | 호출 시점과 인자 |
| --- | --- |
| `def 시작():` | 모든 객체가 준비된 뒤 객체마다 한 번 호출한다. |
| `def 키_클릭(누른_키):` | 키를 처음 눌렀을 때 키 이름을 전달한다. |
| `def 키_클릭_중(누른_키):` | 누르고 있는 각 키에 대해 최신 갱신마다 호출한다. |
| `def 키_클릭_끝(누른_키):` | 키를 놓았을 때 키 이름을 전달한다. |
| `def 자신_클릭():` | 자신을 마우스 왼쪽 버튼으로 누른 순간 호출한다. |
| `def 자신_클릭_중():` | 자신에게 시작한 누름을 유지하는 동안 최신 갱신마다 호출한다. |
| `def 자신_클릭_끝():` | 자신에게 시작한 누름을 해제할 때 호출한다. |
| `def 방송_받기(신호_이름):` | 방송한 문자열을 전달한다. |
| `def 닿았을_때(이름_리스트):` | 새로 닿은 캐릭터 이름 목록을 전달한다. |
| `def 닿는_중(이름_리스트):` | 현재 닿은 캐릭터 이름 목록을 최신 갱신마다 전달한다. |
| `def 닿는_중_종료(이름_리스트):` | 떨어진 캐릭터 이름 목록을 전달한다. |

방향키는 `"왼쪽"`, `"오른쪽"`, `"위"`, `"아래"`이다. 스페이스·Enter·Escape는 `"스페이스"`, `"엔터"`, `"탈출"`이다. 영문·숫자·기호 한 글자도 전달하며 영문은 소문자이다. 한글 조합 입력과 Ctrl·Alt·Meta 조합 단축키는 게임 입력으로 처리하지 않는다.

겹친 캐릭터 중 가장 앞의 보이는 캐릭터가 클릭을 받는다. 빈 곳에서 누르면 배경.py의 자신 클릭 이벤트가 받는다. 누른 뒤 포인터가 밖으로 나가도 버튼을 놓기 전까지 최초 대상이 유지된다. 무대 초점을 잃으면 키·마우스 유지 상태를 해제한다.

접촉은 방향에 맞춰 회전한 사각 범위로 확인하며, 숨긴 캐릭터와 물리 모드가 '없음'인 캐릭터는 제외한다. 트리거도 접촉을 전달한다. 이름 목록은 설정의 캐릭터 순서로 전달하며 빈 목록으로 호출하지 않는다. 이름을 바꾸면 이후 목록에는 새 이름이 나온다. 배경과 무대 경계 벽은 접촉 이름 목록에 포함하지 않는다.

유지 이벤트 세 종류는 Python이 처리할 수 있을 때 최신 갱신마다 한 번 호출하며, 이전 호출이 끝나기를 기다리지 않는다. 처리하지 못한 갱신을 나중에 몰아서 호출하지 않는다. 키를 놓거나 클릭·접촉이 끝나면 해당 유지 이동과 새 호출을 멈춘다. 이미 실행한 함수는 끝까지 진행하지만, 끝난 유지 상태의 이동을 뒤늦게 다시 적용하지 않는다. 일반 이벤트에서 이미 시작한 이동은 유지 상태의 해제로 취소되지 않는다. 키·클릭·방송의 일반 이벤트는 같은 호출이 실행 중이면 재입력을 무시한다. 서로 다른 키·방송 신호는 별도로 실행할 수 있다.

키·클릭과 접촉의 시작·종료는 발생 순서대로 전달한다. 접촉 시작·종료는 각 전환마다 별도로 호출하므로, 이전 접촉 함수가 기다리는 중에도 다음 접촉 함수가 실행된다. Python이 다른 처리를 하는 동안 여러 번 닿았다가 떨어진 경우에도 각 시작·종료를 한 번씩 받으며, 각 함수 안의 명령은 순서대로 실행한다.

## 이동과 상태

무대는 800×600이며 중앙이 `(0, 0)`이다. 오른쪽·위쪽이 양수이고 방향은 오른쪽 0도, 반시계 방향 양수이다.

| 코드 | 일반 이벤트 | 유지 이벤트 |
| --- | --- | --- |
| `앞으로(100)` | 총 100만큼 이동하고 완료를 기다린다. | 초당 100의 이동량으로 계속 움직인다. |
| `왼쪽으로돌기(90)` | 왼쪽으로 총 90도 돌고 완료를 기다린다. | 초당 90도만큼 왼쪽으로 회전한다. |
| `오른쪽으로돌기(90)` | 오른쪽으로 총 90도 돌고 완료를 기다린다. | 초당 90도만큼 오른쪽으로 회전한다. |
| `뒤집기("가로")` | 캐릭터 모양을 좌우로 한 번 뒤집는다. | 호출될 때마다 한 번 뒤집는다. |
| `뒤집기("세로")` | 캐릭터 모양을 위아래로 한 번 뒤집는다. | 호출될 때마다 한 번 뒤집는다. |
| `좌표로(100, 0)` | 지정한 좌표로 즉시 이동한다. | 동일하다. |
| `바라보기(90)` | 방향을 즉시 90도로 정한다. | 동일하다. |
| `바라보기(100, 0)` | 현재 위치에서 지정 좌표를 향한다. | 동일하다. |
| `기다리기(1)` | 현재 호출을 1초 기다린다. | 현재 호출만 기다리고 최신 갱신의 새 호출은 계속된다. |

속도는 기본값 1인 배율이다. 일반 이동은 초당 `200 × 속도`, 일반 회전은 초당 `180 × 속도`로 진행한다. 유지 이동·회전은 `명령의 값 × 속도`를 초당 변화량으로 사용한다. 한 유지 호출 안의 이동·회전은 합산하고, 같은 유지 이벤트의 다음 호출에서는 현재 호출이 지정한 이동 상태로 바꾼다. 새 호출에 이동 명령이 없으면 이전 유지 이동은 멈춘다. 서로 다른 키나 다른 이벤트의 상대 동작은 합산한다. 유지 이벤트에서 방향을 직접 지정하지 않은 `앞으로`는 계속 바뀌는 차체 방향을 따라간다. 전진과 회전을 함께 누르면 곡선으로 이동한다. 같은 유지 호출에서 `바라보기`나 방향 대입을 먼저 하면 그 방향의 이동량으로 등록하므로 화면 기준 방향키 조작도 유지된다. 음수 이동은 반대 방향이다.

```python
def 자신_클릭():
    앞으로(100)
    말하기("100만큼 이동했어요!")
```

위 코드에서는 이동이 끝난 위치·방향을 반영한 뒤 말한다. 다른 이벤트는 이동 중에도 실행된다. 유지 이벤트 안의 숫자는 거리가 아닌 속도이므로, 매 프레임의 이동량을 학생이 직접 계산할 필요가 없다. 실행부가 이동·물리·장면을 독립적으로 갱신하므로 Python이 다른 처리를 하는 동안에도 이미 시작한 이동은 계속된다.

`뒤집기`의 가로·세로 상태는 서로 독립적이며 같은 축으로 두 번 호출하면 원래 모양으로 돌아온다. 캐릭터의 원래 모양을 기준으로 뒤집은 뒤 기존 방향 각도만큼 회전하여 그린다. 위치·방향·이동량·충돌 범위·물리 상태는 바꾸지 않으며 이름표와 말풍선도 뒤집지 않는다. 새 실행은 두 축 모두 뒤집지 않은 상태로 시작한다. `"가로"`와 `"세로"` 이외의 값은 오류이다.

오른쪽으로 간 뒤 왼쪽을 보는 모양으로 돌아오려면 방향은 0도로 유지하고 음수 거리와 함께 사용한다.

```python
def 시작():
    바라보기(0)
    앞으로(100)
    뒤집기("가로")
    앞으로(-100)
```

한 번만 뒤집는 활동에는 `시작`, `키_클릭`, `자신_클릭` 같은 일반 이벤트를 사용한다. `키_클릭_중` 같은 유지 이벤트에 넣으면 호출마다 모양이 다시 뒤집힌다.

| 상태 | 의미와 변경 예 |
| --- | --- |
| `이름` | 현재 읽기 전용 이름이다. 초기값은 프로젝트 설정이며 `이름_정하기("새이름")`으로 바꾼다. |
| `위치` | 가로·세로 튜플이다. `위치 = (100, 0)`으로 즉시 설정한다. |
| `방향` | 도 단위 각도이다. `방향 += 90`으로 즉시 바꾼다. |
| `속도` | 0보다 큰 유한한 배율이다. `속도 = 2`는 두 배이다. |
| `크기` | 원본 대비 0.1~5 배율이다. `크기 = 2`는 두 배 크기이다. |
| `가시성` | True 또는 False이다. `가시성 = False`로 숨긴다. |
| `배경` | 배경 파일에서만 사용하는 배경 모양이다. `배경 = "forest"`처럼 설정한다. |

상태 이름은 항상 해당 객체의 속성을 가리키며 global이 필요하지 않다. 같은 이름을 함수의 매개변수나 별도 함수 이름으로 쓰지 않는다. 위치·방향의 절대 대입은 진행 중인 다른 호출의 상대 이동을 취소하지 않는다.

`속도_변경(1)`과 `크기_바꾸기(1)`은 현재 값에 더한다. `크기_정하기(1)`과 `가시성_설정(True)`는 지정 값으로 설정한다. 배경에서 캐릭터 전용 함수를 호출하면 아무 효과 없이 즉시 끝나고 다음 코드로 진행한다. 이동·회전·뒤집기·좌표·방향·속도·크기·가시성 변경, 물리·무게 설정, 힘·정지와 이름 변경 함수에 적용하며 이전 회전 함수 이름도 같다. 함수 안의 값 검증이나 이동 대기는 수행하지 않는다. 다만 인자 표현식은 일반 Python처럼 먼저 계산하므로 정의하지 않은 변수를 넘기면 오류가 난다.

`위치`, `방향`, `속도`, `크기`, `가시성`, `물리`, `무게`, `닿은_객체_리스트` 같은 캐릭터 전용 상태 값의 읽기·직접 대입은 배경에서 지원하지 않는다. 함수 호출을 무시하는 규칙과 구분한다. `말하기`, `기다리기`, `방송하기`, 계산·입력·다른 캐릭터 조회는 배경에서도 정상 동작한다.

`왼쪽_돌기(90)`와 `오른쪽_돌기(90)`도 사용할 수 있다. 기존 `왼쪽으로돌기`와 `오른쪽으로돌기`는 같은 동작으로 유지한다. `속도`는 명령 이동·회전의 배율이며, 중력이나 충격으로 생긴 물리 속도를 바꾸지 않는다.

## 물리와 충돌

물리는 0.1.1부터 제공한다. 물리 엔진은 .NET 실행부에 포함되어 있으므로 Python용 물리 패키지나 학생 코드의 import는 필요하지 않다.

| 모드 | 동작 |
| --- | --- |
| `"없음"` | 명령으로 움직이며 접촉·물리 계산에 참여하지 않는다. |
| `"충돌만"` | 기본값이다. 명령으로 움직이고 접촉을 감지하며 다른 충돌 객체와 무대 경계에 막힌다. 힘과 중력으로 밀리지는 않는다. |
| `"물리"` | 무게·충격·중력과 충돌에 따라 움직인다. 무대 사방의 벽에 막히고 자동으로 회전하지 않는다. |

0.1.7부터 '충돌만' 객체끼리도 서로 통과하지 않는다. 상대를 질량에 따라 밀어내지는 않는다. 원본 크기와 크기 배율로 만든 사각형이 방향에 따라 함께 회전한다. 회전 경로에 벽이나 무대 경계가 있으면 닿기 직전에서 멈추므로 후진하거나 반대로 돌아 공간을 만들어야 한다.

`물리_설정(모드, 트리거=False)`의 트리거는 불리언 값이며 생략하면 False이다. 어느 한쪽이 True이면 서로 통과하지만 접촉 이벤트는 계속 발생한다. 보급품·도착 지점에는 True를 사용한다. 트리거는 무대 경계도 통과하며, '물리' 모드에서는 중력과 충격이 유지된다. 모드 '없음'은 트리거와 관계없이 접촉에서 제외한다. `바라보기`·방향 대입·`좌표로`는 즉시 배치이므로 이동·회전 경로를 검사하지 않는다. 물리 모드를 바꾸면 이전 물리 속도를 지운다. 숨긴 객체는 물리 계산과 접촉에서 제외하고 다시 보일 때 현재 위치에서 물리 속도 0으로 시작한다.

| 코드 | 동작 |
| --- | --- |
| `물리` | 현재 모드 문자열을 읽는다. |
| `물리_설정("물리")` | 모드를 지정하며 트리거를 False로 설정한다. |
| `물리_설정("충돌만", 트리거=True)` | 통과하면서 접촉을 감지하는 객체로 설정한다. |
| `무게` | 물리 계산에 사용하는 질량을 읽는다. 기본값은 1이다. |
| `무게_설정(10)` | 무게를 0.001~100000의 유한한 숫자로 정한다. |
| `힘_작용(90, 6)` | 90도 방향으로 크기 6의 순간 충격을 한 번 준다. '물리' 모드에서 사용한다. |
| `정지()` | 현재 물리 속도를 0으로 만든다. 중력과 이후 충돌은 계속 작용하며 실행 중인 이동 명령을 취소하지 않는다. |
| `닿은_객체_리스트` | 현재 닿은 캐릭터의 이름 목록을 읽는다. 반환받은 목록을 바꾸어도 접촉 상태는 바뀌지 않는다. |

방향은 오른쪽 0도·위쪽 90도이다. 힘의 크기는 순간 충격량이며, 같은 충격에서 무게가 두 배이면 속도 변화는 절반이다. 내부 기준은 무대 100단위가 1m, 무게가 kg, 충격량이 N·s이며 중력은 아래쪽으로 초당 속도를 980단위씩 증가시킨다. 유지 이벤트에서 힘을 반복 호출하면 충격도 반복해서 더해진다.

```python
def 시작():
    물리_설정("물리")
    무게_설정(1)


def 키_클릭(누른_키):
    if 누른_키 == "스페이스":
        힘_작용(90, 6)
```

'물리' 객체의 앞으로 이동은 벽이나 다른 충돌 객체에 막힐 수 있다. 명령은 원래 이동 시간 뒤에 끝나지만 실제 이동 거리는 짧아질 수 있으며, 다음 줄에서는 충돌을 반영한 위치를 읽는다. `좌표로`와 위치 대입은 중간 장애물을 건너뛰는 절대 배치이며, '물리' 객체는 사각 범위 전체가 무대 안에 있도록 위치를 제한한다. '물리' 모드의 크기는 무대보다 클 수 없다. 크기를 바꾸면 충돌 범위도 바뀐다.

배경은 물리 상태가 없다. 배경에서 물리·무게 설정, 힘·정지 함수는 무시하며 접촉 이벤트 함수는 등록하거나 호출하지 않는다. [물리 예제](../samples/06-physics/README.md)에서 공의 낙하·충격·정지를 확인할 수 있다.

## 표현·계산·조회

| 코드 | 동작 |
| --- | --- |
| `말하기("안녕!")` | 캐릭터 말풍선에 표시한다. 배경 파일에서는 무대 안내 문구이다. |
| `말하기(누른_키, "키를 눌렀구나!")` | 여러 문자열 사이에 공백을 넣어 표시한다. 예를 들어 오른쪽 키는 '오른쪽 키를 눌렀구나!'로 표시한다. |
| `말하기("점수:", 3, 시간=1.5)` | 값을 문자열로 바꾸어 '점수: 3'을 1.5초 동안 표시한다. 해당 호출은 표시가 끝날 때까지 기다린다. |
| `말하기("")` | 자신의 말풍선 또는 배경 안내를 지운다. |
| `방송하기("인사")` | 자신을 포함한 배경과 모든 캐릭터에 신호를 전달한다. 수신 완료는 기다리지 않는다. |
| `랜덤(0, 10)` | 양끝을 포함한 0~10의 무작위 정수를 반환한다. |
| `각도로(10, 10)` | 원점에서 해당 벡터를 향하는 각도를 반환한다. |
| `위치_구하기("자동차")` | 지정한 캐릭터의 현재 위치 튜플을 반환한다. |
| `방향_구하기("자동차")` | 지정한 캐릭터의 현재 방향을 반환한다. |
| `이름_정하기("새이름")` | 자신의 이름을 이번 실행 동안 바꾼다. 배경에서는 무시한다. |
| `print("완료")` | 웹 콘솔에 Python 출력을 남긴다. |

0.1.4부터 말하기는 print처럼 0개 이상의 값을 받아 str로 바꾸고 공백 하나로 이어 표시한다. 말하기()도 안내를 지운다. 공백과 변환된 내용을 합해 200자 이내여야 하며 소리를 내지 않는다. print의 sep·end·file·flush 옵션은 제공하지 않는다.

시간은 초 단위의 키워드 인자이며 0~3600의 유한한 정수·실수를 받는다. 생략하거나 None이면 바로 다음 줄로 진행하고 말풍선을 계속 표시한다. 시간을 정하면 현재 호출만 기다리며 다른 객체·이벤트는 계속 실행한다. 지정 시간이 끝나면 그 메시지를 지우고 다음 줄로 진행한다. 다른 호출이 새 메시지를 표시했다면 이전 호출의 시간이 끝나도 새 메시지는 지우지 않는다. 배경 안내에도 같은 규칙을 적용한다. 시간 0은 바로 끝나며 bool·음수·무한대·NaN·문자열 시간은 거절한다. 시간을 정한 말하기는 시작 또는 이벤트 함수에서 사용하며 파일 초기화 부분에서는 사용하지 않는다.

상대 이름은 해당 캐릭터의 현재 이름과 일치해야 한다. 이름 변경은 비어 있지 않은 1~80자의 서로 다른 이름을 사용하며 '배경'은 예약되어 있다. 변경 뒤 기존 이름으로 조회하면 오류가 나고 이후 접촉 목록에는 새 이름이 나온다. 파일명과 project.json은 바뀌지 않으며 다시 시작하면 설정 이름으로 돌아간다. `이름 = ...` 대입은 지원하지 않는다. 함수 호출에는 콜론을 붙이지 않는다.

## 텍스트 입력

0.1.1부터 `input()`은 실행기 콘솔의 출력 다음 줄에 질문과 입력칸을 표시한다. Enter 또는 입력 보내기 버튼으로 제출하면 문자열을 반환하고, 질문과 제출한 답이 콘솔 출력으로 남는다. 질문을 생략한 `input()`도 사용할 수 있다. 학생 코드에는 별도 import나 await가 필요하지 않다.

```python
대답 = input("어떤 이름으로 불러 드릴까요?")
print("반가워요, " + 대답)


def 시작():
    거리 = int(input("몇 칸 움직일까요?"))
    앞으로(거리)
    말하기("도착했어요!")
```

숫자를 입력해도 반환값은 문자열이다. 정수 계산에는 `int()`, 소수 계산에는 `float()`로 변환한다. 빈 문자열과 앞뒤 공백도 그대로 반환하므로 숫자로 바꿀 수 없는 답은 Python의 변환 오류가 된다. 위 예제의 `대답`처럼 일반 변수 이름을 사용하며, `이름`은 캐릭터의 읽기 전용 상태이므로 답을 저장하는 변수로 사용하지 않는다.

파일 맨 위와 시작·일반 이벤트, 그 안에서 호출하는 보조 함수에서 사용할 수 있다. 파일 맨 위에서 입력받는 동안에는 프로젝트 초기화를 기다리며, 모든 파일의 초기화가 끝난 뒤 시작 이벤트를 실행한다. 이벤트 안에서 입력받을 때는 해당 호출만 기다리고 다른 이벤트와 이동은 계속된다.

여러 호출이 동시에 질문하면 요청한 순서대로 하나씩 표시한다. 여러 탭에서 같은 질문에 답하면 먼저 접수된 답 하나만 사용한다. 질문은 최대 2,000자, 답은 줄바꿈 없는 한 줄로 최대 4,096자이며 브라우저와 같은 UTF-16 길이를 기준으로 한다. 이모지 등 일부 문자는 두 자리로 계산한다.

키·자신 클릭·접촉의 유지 이벤트는 최신 갱신마다 반복 호출되므로 그 안의 input은 오류로 안내한다. 질문은 시작 또는 일반 이벤트에 둔다. 중지·재시작·실행 종료 시 남은 질문을 취소하며 이전 실행의 답은 새 실행으로 전달하지 않는다. 입력칸에 쓰는 동안 키는 게임 조작으로 보내지 않는다. 답을 보낸 뒤 게임을 조작하려면 무대를 클릭하여 초점을 옮긴다.

입력한 답은 브라우저 저장소에 기록하지 않는다. 제출한 질문과 답은 이번 실행의 일반 출력과 같은 범위로 콘솔에 남으며, 새 실행에서는 이전 출력과 함께 지운다. 학생 코드에서 `print(대답)`을 호출하면 별도의 출력으로 한 번 더 표시된다. 이 기능은 학생 스크립트의 input을 콘솔 입력칸에 연결하며, 외부 터미널 표준입력이나 외부 모듈의 `sys.stdin` 입력을 제공하는 기능은 아니다.

## 교사 프로젝트 설정

다음은 최소 프로젝트 설정의 예이다.

```json
{
  "background": { "file": "배경.py", "kind": "city" },
  "actors": [
    {
      "name": "고양이", "file": "고양이.py", "kind": "cat",
      "x": -160, "y": -80, "heading": 0,
      "scale": 1, "speed": 1, "visible": true
    }
  ]
}
```

배경·캐릭터 파일은 프로젝트 바로 아래에 둔 .py 파일이어야 하며, 서로 다른 파일을 지정한다. 경로 이동과 연결 파일은 허용하지 않는다. 캐릭터 이름은 중복할 수 없고 배경이라는 이름은 예약되어 있다. 캐릭터는 최대 64개이며 목록의 뒤쪽 항목을 앞에 그린다.

생략한 캐릭터 위치·방향은 0, 크기·속도 배율은 1, 가시성은 True이다. 기본 캐릭터 모양은 cat, 기본 배경 모양은 plain이다. 선택 항목인 `physics`의 기본값은 `"충돌만"`, `mass`의 기본값은 1, `trigger`의 기본값은 false이다. `"trigger": true`로 통과·접촉 객체를 준비한다. 예를 들어 `"physics": "물리", "mass": 2`는 처음부터 무게 2의 물리 객체로 준비한다.

- 배경 모양: `plain`, `city`, `dance`, `track`, `court`, `forest`
- 캐릭터 모양: `cat`, `car`, `rabbit`, `ball`, `bat`, `ghost`, `star`, `basket`, `paddle`, `rocket`, `flag`, `planet`

설정 변경도 다음 시작부터 반영된다. 웹에서 읽는 실행 중 프로젝트 정보는 이번 실행에 고정한 설정이다.

### 프로젝트 이미지

준비된 모양 외의 배경이나 캐릭터 그림은 BlackPy에 추가하지 않고 프로젝트의 `_blackpy` 폴더에 둔다. 배경과 캐릭터의 선택 항목인 `image`에 그 폴더의 파일 이름을 적으면 웹 무대가 해당 그림으로 그린다.

```json
{
  "background": { "file": "배경.py", "kind": "plain", "image": "우주센터.svg" },
  "actors": [
    {
      "name": "로켓", "file": "로켓.py", "kind": "rocket", "image": "로켓.svg",
      "x": 0, "y": -110, "heading": 90, "scale": 1.5
    }
  ]
}
```

- 이미지는 `project.json`과 같은 폴더에 둔 png·jpg·gif·webp·svg 파일이며 하위 폴더·경로 이동·연결 파일은 허용하지 않는다. 파일 하나는 5MB 이하이다. 이전 형식처럼 `project.json`이 프로젝트 바로 아래에 있으면 그 폴더에서 찾는다.
- 배경 이미지는 무대 전체 800×600에 맞추어 그린다. 실행 중 `배경`을 다른 모양으로 바꾸면 그 모양을 그리며, 설정한 `kind`로 되돌리면 이미지를 다시 그린다.
- 캐릭터 이미지는 `kind`의 기본 크기에 `scale`을 곱한 상자를 채운다. 방향 0도에서 오른쪽을 보는 그림으로 만들며 회전·뒤집기·숨기기는 기본 모양과 같다. 클릭·접촉·물리 판정도 `kind`의 상자 크기를 사용한다.
- 설정한 이미지가 없거나 형식이 맞지 않으면 실행을 시작하지 않고 파일 이름을 안내한다. 이미지는 웹이 프로젝트 정보를 읽을 때 함께 불러오므로 그림을 바꾸면 다음 시작부터 반영된다.
- 이미지는 설정에 적힌 이름으로만 웹에 전달한다. SVG는 무대의 그림으로만 사용하며 스크립트나 외부 파일을 불러오지 않는 그림을 사용한다.

## 배포와 이전 형식

소스 저장소에서 다음 명령으로 배포한다.

```powershell
./scripts/Publish.ps1
./scripts/Publish.ps1 -Destination 'C:/Classroom/blackpy-new'
```

출력은 지정한 배포 루트 아래 실습 폴더이다. 실행부·Python 지원 모듈·라이선스는 `_blackpy/_runtime`에 들어간다. 배포 폴더 전체를 함께 전달하며 Python 외부 패키지는 설치하지 않는다.

재배포는 기존 학생의 Python 파일과 project.json을 보존하고 없는 기본 파일만 추가한다. 기존 main.py만 있는 구형 실습 폴더에는 배포를 중단하고 새 목적지를 안내한다. 기존 학생 파일·이전 예제 폴더를 자동 삭제하지 않는다.

현재 형식은 이전 Actor·stage·playground API와 15개 놀이 예제를 지원하지 않는다. 기존 수업 HTML과 교안의 코드·파일 구성·입력 설명은 새 형식으로 개편해야 하며, 이 저장소의 배포가 수업 자료를 자동 수정하지 않는다.

## 오류와 실행 제약

콘솔에 표시된 파일과 줄을 확인하고 수정·저장한 뒤 다시 시작한다. 실행 도중 파일을 저장했더라도 오류는 이번 실행에 고정한 코드의 줄을 기준으로 한다.

지원하는 작성 방식은 일반 def와 조건문·반복문·계산이다. 클래스 선언, 명시적 async/await, yield는 학생 스크립트에서 지원하지 않는다. 외부 Python 패키지 설치와 터미널 표준입력은 제공하지 않으며 학생 스크립트의 input은 웹 입력칸에 연결한다. 라이브러리의 긴 동기 호출까지 자동 비동기로 바꾸지 않으므로 시간 대기는 제공된 기다리기를 사용한다.

활성 호출이 4,096개를 넘으면 오류로 종료한다. 유지 이벤트 안의 긴 기다리기나 끝나지 않는 반복은 이전 호출이 남은 채 계속 새 호출을 만들 수 있다. 일반 보조 함수의 이동은 호출한 이벤트의 일반·유지 규칙을 이어받는다.

폴더 배포본의 실행부는 PYTHON_EXE, PATH의 python, py -3 순서로 Python을 찾는다. 설치형의 `blackpy run`은 자신을 실행한 Python 경로를 PYTHON_EXE로 전달한다. 실행부의 개발용 옵션은 `--project <프로젝트 폴더>`, `--no-browser`, `--port <번호>`이며 포트 0은 자동 선택이다. 실행부는 접속 주소를 PLAYGROUND_URL로 출력한다.
