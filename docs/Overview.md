# BlackPy 개요

BlackPy는 배경과 캐릭터별 Python 코드의 동작을 로컬 웹 무대에서 보여 주는 교육용 실행 환경이다.

## 소개

| 항목 | 내용 |
| --- | --- |
| 개요 | 파일별 캐릭터 코드와 웹 입력을 연결하고 움직임·출력을 보여 주는 프로그램이다. |
| 목적 | 학생이 이벤트와 Python 문법으로 행동을 작성하고 예상과 결과를 비교하게 하는 것이다. |
| 구현 | 프로젝트 설정, Python 실행기, 로컬 실행부, 웹 무대를 같은 실행 생명주기로 연결한다. |

학생의 코드는 편집기에 남으며, 웹은 실행과 관찰·명령 복사를 담당한다. 학생에게 서버 설정, 클래스 선언, 자기 객체 참조나 비동기 제어 문법을 요구하지 않는다.

## 학습 흐름

교사는 배경과 캐릭터가 준비된 프로젝트를 전달한다. 학생은 웹에서 대상과 명령을 고르고 코드 행을 클릭하여 복사한 뒤, 해당 Python 파일에 붙여 넣고 저장한다. 시작하면 동작을 확인할 수 있고, 수정 후 다시 시작하면 새 코드가 반영된다.

프로젝트는 실행부의 별도 콘솔 창 없이 브라우저로 열리며, 마지막 웹 화면을 닫으면 로컬 실행부도 자동 종료된다. 설치형 명령을 입력한 터미널은 실행부가 끝날 때까지 기다린다.

파일 하나의 코드는 해당 배경 또는 캐릭터의 행동을 정의한다. 화면에서 선택한 대상은 명령 안내와 파일 표시를 바꾸며, 실행 중인 코드의 주체를 바꾸지 않는다. 캐릭터를 추가하고 초기 모양·위치를 정하는 작업은 교사의 프로젝트 설정에서 처리한다.

## 구성과 관계

| 구성 | 책임 |
| --- | --- |
| 프로젝트 설정 | 배경·캐릭터 파일, 이름·모양·초기 상태와 그리기 순서를 정한다. |
| 학생 Python 파일 | 일반 함수와 명령으로 해당 객체의 행동을 작성한다. |
| Python 실행기 | 파일별 객체·명령과 이벤트를 실행하고, 이동 완료·입력·대기에 따른 코드 순서를 관리한다. |
| 로컬 실행부 | 설정·코드를 고정하고, 독립된 시계로 이동·물리·장면을 갱신하며 프로세스·입력·종료를 관리한다. |
| 웹 무대 | 장면·콘솔을 표시하고 실행 버튼·입력·코드 복사를 제공한다. |
| 설치·프로젝트 도구 | 공통 실행부를 Python 환경에 설치하고, 학생 프로젝트 생성과 실행을 연결한다. |
| 편집기 명령 안내 | 학생 코드에 가져오기 문장을 요구하지 않고 전용 명령·상태를 편집기에 알린다. |

## 실행과 이벤트

서로 다른 이벤트는 함께 실행되며, 한 이벤트 호출 안의 명령은 순서대로 실행된다. 일반 이벤트에서 이동은 완료된 위치·방향을 받은 뒤 다음 줄로 진행한다. 유지 이벤트에서는 이동 값이 초당 이동량이며, 실행부가 유지 중인 이동·회전을 시간에 맞춰 진행한다.

키·클릭·방송의 일반 이벤트는 같은 호출이 진행 중이면 재입력을 무시한다. 접촉 시작·종료는 전환마다 별도로 호출하므로 이전 접촉 함수가 기다리는 중에도 다음 전환의 함수가 실행된다.

로컬 실행부의 이동·물리·장면 갱신은 최대 60Hz이며 Python의 응답 속도와 분리된다. Python이 다른 처리를 하는 동안에도 이미 등록한 이동과 중력은 계속된다.

키와 자신 클릭에는 시작·유지·종료 이벤트가 있다. 접촉에도 새로 닿음·닿는 중·떨어짐을 구분한다. 유지 이벤트는 Python이 처리할 수 있을 때 최신 갱신마다 한 번 호출하며, 놓친 갱신을 몰아서 실행하지 않는다. 이전 호출이 기다리는 중이어도 새 호출은 시작할 수 있다. 상태가 끝나면 유지 이동과 새 호출을 멈추고 이미 시작한 함수는 끝까지 실행한다. 해당 상태가 끝난 뒤 이전 호출이 내보낸 유지 이동은 다시 적용하지 않는다.

방송은 배경과 모든 캐릭터가 같은 신호를 받을 수 있는 방법이다. 배경은 캐릭터가 없는 곳에서 시작한 클릭을 받는다. 캐릭터가 겹치면 가장 앞의 보이는 캐릭터가 클릭을 받는다.

## 제공 범위와 제약

기본 프로젝트는 배경·고양이·자동차로 구성된다. 이동·회전·크기·가시성·말풍선, 키·클릭·방송·접촉 이벤트, 난수·각도·다른 캐릭터 상태 조회와 실행 중 이름 변경을 제공한다. 변수와 공통 함수 생성 기능은 보류하며, 웹의 캐릭터 생성·설정 편집은 제공하지 않는다.

무대의 논리 크기는 800×600이다. 중앙이 원점이며 오른쪽과 위쪽이 양수이다. 객체마다 '없음', '충돌만', '물리' 모드를 선택한다. 기본값인 '충돌만'은 접촉을 감지하고 물리 객체를 막지만 힘과 중력으로 움직이지 않는다. '물리' 객체는 무게에 따른 충격과 중력을 받고 무대의 사방 경계에 막힌다. '없음'과 숨긴 객체는 접촉에서 제외한다.

물리와 접촉은 캐릭터의 회전을 반영하지 않는 사각 범위를 사용한다. 방향 전환 명령은 그림과 이동 방향을 바꾸지만 물리적인 자동 회전은 발생하지 않는다. 물리 계산은 C# 실행부에 동봉한 Box2D.NET이 담당하므로 학생 Python 환경에 별도 패키지를 설치하지 않는다. 소리는 제공하지 않는다.

학생 스크립트의 input은 실행기 콘솔에서 한 줄을 받아 문자열로 반환하고, 질문과 제출한 답을 이번 실행의 출력으로 남긴다. 질문은 실행 전체에서 순서대로 표시하며, 이벤트의 입력 대기는 다른 이벤트의 실행을 막지 않는다. 파일 초기화 중에도 입력받을 수 있으나 반복 호출되는 유지 이벤트의 질문은 허용하지 않는다.

실행 시 프로젝트 설정과 등록된 모든 스크립트를 고정한다. 별도로 가져오는 외부 모듈까지 복제하지 않는다. 실행 중 코드 교체와 터미널 표준입력은 제공하지 않는다. 브라우저 저장소에는 학생 코드·답·완료 상태·실행 기록을 저장하지 않는다.

## 배포와 수업 자료

설치형 배포는 공통 실행부를 Python 환경에 두고 학생 프로젝트를 별도 폴더에 둔다. 프로젝트마다 실행부를 복사하지 않으며 패키지 재설치·제거가 학생 코드를 변경하지 않는다. 폴더 배포는 새 기본 프로젝트와 공통 실행부가 있는 실습 폴더 전체를 전달하는 방식이다. 두 배포 방식 모두 실행부의 라이선스·제3자 고지를 포함한다.

새 프로젝트 생성은 기존 파일이 있는 폴더를 거절하고, 폴더 재배포는 기존 학생 코드와 프로젝트 설정을 보존한다. 편집기 지원은 전용 명령을 알려 주되 일반 이름 오류 검사를 유지하며, 학생 파일의 실행 의미를 바꾸지 않는다.

이전 단일 main.py 방식과 15개 놀이 예제는 폐기한 형식이다. 이전 API에 기반한 수업 HTML과 교안은 그대로 사용할 수 없으며, 새 이벤트·명령과 파일 구성에 맞게 개편해야 한다. 이번 실행부 개편은 기존 학생 자료를 자동 변환하지 않는다.
