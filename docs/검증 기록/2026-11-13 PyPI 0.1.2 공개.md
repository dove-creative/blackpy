# BlackPy 0.1.2 공개 검증 기록

## 목적과 변경

이전 로컬 wheel과 정식 공개본이 모두 0.1.1로 표시되어 pip가 갱신을 생략하는 문제를 해결하기 위한 버전 갱신이다. 오류가 발생한 Python 3.10 설치본은 물리 명령이 없는 로컬 wheel임을 확인하였다. 물리·입력·독립 시뮬레이션의 기능은 유지하며 패키지 버전과 검증 대상, 설치·갱신 안내를 0.1.2로 변경하였다.

버전 갱신 커밋은 [c9092356c5cae1f6334ea4a905e7e45a8a2473a2](https://github.com/dove-creative/blackpy/commit/c9092356c5cae1f6334ea4a905e7e45a8a2473a2)이며, 이벤트 검사의 완료 대기 보완을 포함한 릴리스 소스는 [3b6996a6c8dbd1da7cec45058fcb57978e8e89d1](https://github.com/dove-creative/blackpy/commit/3b6996a6c8dbd1da7cec45058fcb57978e8e89d1)이다. 기존 문서 정리와 학생 예제 편집, 설계 원본은 이번 릴리스 커밋에서 제외하였다.

## 로컬 환경과 결과

2026-11-13 KST의 Windows x64 개발 컴퓨터에서 .NET SDK 10.0.404, Python 3.13.18, Node.js 24.15.0, PowerShell 7.6.9를 사용하였다. 컨벤션 서브모듈은 저장소에 기록된 30dc756c7422348654589e58cc5f1fb942651cbf를 유지하였다. 의존 NuGet 패키지는 변경하지 않았다.

| 실행 통합·물리·시뮬레이션·입력·브라우저 수명 | 36/36 통과이다. |

| 배포 | 별도 10개 항목 통과이다. |

테스트 러너 합계는 322/322이다. 전체 명령과 단계별 로그는 artifacts/release-0.1.2/validate.ps1, local-results.json과 각 단계의 로그에 보관하였다. 제한된 실행 환경의 첫 C# 테스트는 진행되지 않아 중단하였으며 NuGet 취약성 데이터 조회 경고가 발생하였다. 이후 프로세스·네트워크 접근이 허용된 환경에서 전체 명령을 다시 수행하여 통과하였다.

새 임시 배포본으로 생성한 로컬 wheel은 artifacts/wheels/blackpy-0.1.2-py3-none-win_amd64.whl이다. 크기는 48,975,637바이트이며 SHA-256은 `046826316b3133443a7dc02f5f1b3227c4cf618f1fc009453de7e6e224822f93`이다. Twine strict 검사를 통과하였다. 공개 파일과의 대조에는 별도로 Actions 산출물을 사용한다.

Anaconda Python 3.10.9로 만든 별도 가상환경에서도 로컬 wheel을 설치하였다. CLI 버전·새 프로젝트 생성·학생 공.py의 직접 실행·공의 낙하와 발판 충돌·스페이스 충격·마지막 연결 종료와 학생 파일 보존을 5개 확인 항목으로 검사하여 통과하였다. 결과는 python310-local-verification.json에 있다.

## 원격 공개

최초 [push 검증](https://github.com/dove-creative/blackpy/actions/runs/43364044356)은 이벤트 통합 검사 한 곳에서 실패하였다. 같은 키의 중복 호출을 제한하는 검사에서 두 이동의 합계를 확인하기 전 고정 400ms만 기다려 최종 장면을 보장하지 못하였다. 최대 10초 안에 실제 목표 위치가 반영되는지 기다리도록 바꾸었으며 기존 좌표·호출 횟수 단언은 유지하였다. 수정한 이벤트 검사 6/6이 로컬에서 통과하였다. 수정 과정의 첫 로컬 실행은 다른 검사의 대기문을 잘못 바꾸어 실패하였고, 잘못 적용한 부분을 복원한 뒤 대상 검사만 수정하여 통과하였다. 각각의 로그는 ci-initial-failure.log, event-edit-initial.log, event-completion.log에 있다.

이전 소스의 [사전 검증](https://github.com/dove-creative/blackpy/actions/runs/43364043622)은 중단하고 최종 소스로 다시 검증하였다.

원격 검증 환경은 Windows Server 2025, .NET SDK 10.0.404, Python 3.13.17, Node.js 24.22.2이다. Windows에서 검증한 동일 wheel을 Ubuntu 공개 작업으로 전달하여 재빌드 없이 업로드하였다. 기존 pypi 환경과 Trusted Publishing을 사용했으며 장기 PyPI API 토큰은 사용하지 않았다. 실행 로그는 artifacts/release-0.1.2의 ci-push.log, ci-preflight.log, ci-publish.log에 보관하였다.

## 공개 파일과 설치

공개 페이지는 [PyPI blackpy 0.1.2](https://pypi.org/project/blackpy/0.1.2/)이다. 실제 업로드 시각은 2026-11-13 04:34:23.604034 UTC, 한국 시각으로 같은 날 13:34:23.604034이다.

- 파일은 blackpy-0.1.2-py3-none-win_amd64.whl이다.
- 크기는 48,975,346바이트이다.
- SHA-256은 `965db048ca3ad927bfed75b62092cb54cfcc407f7c9dc8a59eb2773d7dae6f19`이다.

공개 실행의 Actions 산출물을 내려받아 PyPI 메타데이터의 파일 크기·SHA-256과 대조하였다. Python 3.10.9 가상환경에 공개 PyPI 인덱스·캐시 미사용·강제 재설치 옵션으로 공개 파일을 설치하였다. pip 보고서의 다운로드 주소가 files.pythonhosted.org이고 해시가 Actions·PyPI와 일치함을 확인하였다. pip 22.3.1 보고서는 archive_info.hash 필드를 사용하므로 해당 형식을 반영하여 대조하였다.

업로드 직후 최초 설치 시도에는 일반 pip 색인이 0.1.1까지만 표시하여 실패하였다. 색인에 0.1.2가 반영된 뒤 같은 공개 인덱스로 재시도하여 성공하였다. 최초 실패 로그는 public-install-initial.log, 최종 설치 로그와 보고서는 public-install.log와 public-install-report.json에 있다.

공개 파일에서 CLI 버전·프로젝트 생성·학생 파일 직접 실행·물리 명령·낙하·발판 충돌·스페이스 충격·마지막 연결 종료와 학생 파일 보존의 5개 확인 항목이 통과하였다. 검사에는 실제 HTTP·WebSocket과 Python·C# 실행부를 사용하였다. 결과는 public-verification.json에 있다.

오류가 발생했던 기본 Anaconda Python 3.10.9 사용자 환경도 공개 PyPI에서 0.1.1을 0.1.2로 갱신하였다. 이 환경에서도 같은 5개 실행 확인 항목이 통과하였으며, 원래 samples/06-physics의 Python·편집기 안내·설정 5개 파일은 SHA-256이 모두 유지되었다. 설치 시 사용자 Scripts 폴더의 PATH 안내가 표시되었으므로 CLI 확인에는 같은 Python의 `-m blackpy`를 사용하였다. 결과는 anaconda-upgrade.log, anaconda-verification.json과 student-before-upgrade.json에 있다.

## 검증 범위

학생 파일은 임시 복사본으로 검사하였다. SDK가 없는 별도 컴퓨터, 실제 VS Code 버튼 조작과 브라우저 canvas 표시 FPS는 이번 로컬 검증의 대상이 아니다.
