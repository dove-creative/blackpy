# 객체 함수 호출 검증 기록

## 변경 내용

방송 명령과 수신 이벤트를 제거하고 주변 팔레트에 객체 조회를 추가하였다. `객체_구하기("블록").깨지기()`는 블록 파일에서 정의한 함수를 실행한다. 인자·키워드 인자·반환값을 지원하며, 호출자는 대상 함수의 완료를 기다린다. 대상 파일의 상태와 명령을 사용하고 일반 실행 문맥을 적용한다. 같은 파일의 보조 함수를 직접 부르는 기존 동작은 유지한다.

객체 참조는 이름 변경·숨김 뒤에도 동일한 대상을 가리키며 새 조회에는 현재 이름을 사용한다. 없는 객체·함수는 한국어 오류를 표시한다. import한 함수·공유 변수·기본 명령·내부 런타임은 객체 참조의 공개 함수 목록에 포함하지 않는다. 원래 파일과 오류 줄 정보를 유지한다.

기본 프로젝트와 04-object-calls 샘플, 편집기 안내, 사용·구현·검증 문서를 갱신하였다. 기존 방송 예제는 두 객체를 차례로 움직이고 반환값을 받는 예제로 변경하였다. 작업 전부터 있던 전역변수·디스플레이 변경과 작업 중 반영된 이름표 설정을 포함한 현재 작업 트리에서 검증하였으며 해당 변경은 보존하였다.

## 환경과 결과

Windows x64, Python 3.13.18, .NET SDK 10.0.404, Node.js 24.15.0에서 검사하였다. 최종 검증·설치본 버전은 0.1.17이다.

| .NET Release 전체 | 166개 통과 |

자동화 테스트는 합계 446개이며 별도 배포 시나리오도 통과하였다. wheel SHA-256은 `472bf52b94e6cb07c24450e3da9fe5f2de92335f9a694b4e63adc5d9288cc7ef`이다. 설치 대상은 실제 터미널 인터프리터와 VS Code 기본 pygame 환경을 확인하였다. 두 환경에는 이미 동일한 0.1.17 wheel이 설치되어 있어 재설치 없이 파일 전체 대조와 설치본 실행을 검증하였다.

최초 샌드박스 안의 Python 검사는 asyncio 초기화에서 진행되지 않아 중단하고 외부에서 재실행하였다. .NET 검사도 테스트 호스트 연결 시간 초과 후 외부에서 재실행하여 통과하였다. .NET 로그의 NU1900은 NuGet 취약성 데이터 조회 경고이며 테스트 실패는 없었다.

## 확인 범위와 한계

대상 상태, 인자·반환값·순차 대기, 중첩 호출과 배경 호출, 유지 이벤트에서의 일반 실행과 문맥 복원, 다른 이벤트의 병행, 이름 변경 후 참조, 초기화 중 참조 저장, 이름 오류, 원래 소스 위치와 방송 제거를 확인하였다. 실제 실행부의 샘플에서 고양이가 돌아온 뒤 자동차가 움직이는 순서와 두 번 반복한 출력 순서도 확인하였다.

수업 자료는 본수업 5쪽·익힘책 5쪽의 기존 활동을 객체 함수 호출로 변경하였다. 로컬 링크·그림·실습 경로·코드 구문, 수업 예시와 첫 익힘책의 오류·수정 결과 등 7개 실행 시나리오 및 빈 실습 파일을 검사하였다. 생성된 학생용 명령 안내 86개와 교사용 예제 안내 1개를 갱신하였다. 기존 캡처 중 새 실행 결과와 일치하는 그림을 유지하였다.

앱 브라우저 보안 정책이 로컬 HTML 열기를 차단하여 실제 슬라이드 렌더링, 탭 재사용, VS Code 열기 버튼과 Pylance 화면은 확인하지 못하였다. 자동화의 웹 상태 검사는 실제 GUI 확인과 구분한다. 별도 SDK 없는 장비와 Python 3.10 실행, PyPI 공개는 수행하지 않았다.

검증 로그는 `artifacts/object-calls-*.log`, 수업 검증은 `artifacts/verify-object-call-course.py`, 설치본 검증은 `artifacts/verify-installed-object-calls.py`에 있다. 학생 파일에 검증용 정답을 쓰지 않았다. 커밋·푸시는 수행하지 않았다.
