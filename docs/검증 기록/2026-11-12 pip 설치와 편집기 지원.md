# pip 설치와 편집기 지원 검증 기록

## 변경 범위

Windows x64 wheel, 프로젝트 생성·실행·편집기 설정 명령을 추가한 변경의 검증 기록이다. 학생 프로젝트는 설치 패키지 밖에 생성하며 기존 폴더 배포 방식도 유지한다. 편집기에는 `__builtins__.pyi`로 BlackPy 명령을 알린다. 일반 이름 오류 진단은 끄지 않는다.

## 실행 환경

2026-11-12 Windows x64 개발 컴퓨터에서 Python 3.13.18, Node.js 24.15.0, .NET SDK 10.0.404, PowerShell 7.6.9를 사용하였다. wheel 빌드 도구는 별도 가상환경의 build 1.6.1, Hatchling 1.33.0, Twine 6.2.0이며 편집기 검사기는 Pyright 1.1.414이다.

최초 테스트 러너 집계는 총 155개 중 154개 통과, 1개 실패이다. 의존성·배포 스크립트 확인 항목은 이 수치에 합산하지 않는다. 실패한 샘플은 아래 후속 검증에서 복원 후 통과하였다.

설치형 통합 검증은 한글·공백이 있는 임시 경로에 wheel을 설치하였다. 진입점 `blackpy.exe`가 설치된 가상환경의 Python을 학생 실행에 사용하며, 외부 `PYTHON_EXE`의 잘못된 값에 영향을 받지 않음을 확인하였다. 말하기·좌표 이동을 실행하고 마지막 WebSocket 연결을 닫은 뒤 CLI까지 종료 코드 0으로 끝났다. 재설치와 제거 후 학생 코드와 stub이 그대로 남았다.

wheel 내부의 실행 파일, `coreclr.dll`, 웹 화면, Python 지원 모듈, 기본 프로젝트와 BlackPy·UniEngine·BlackboxSystem·동봉 런타임 고지를 확인하였다. Python 실행 의존성이 없고 최소 Python 버전이 3.10이며 bytecode 캐시가 포함되지 않음을 확인하였다.

Pyright는 `말하기("안녕")`, 이동·방향·조회 명령을 오류 없이 인식하였다. `말하가("오타")`는 `reportUndefinedVariable`, `말하기(123)`은 `reportArgumentType`으로 검출하였다. 실제 VS Code 화면을 연 검증과는 구분한다.

## 검증 중 확인한 문제

- 최초 패키지 설정에서 Hatch의 `targets` 목록과 하위 설정 테이블이 충돌하였다. 명시적인 `--wheel` 빌드로 정리하였다.
- Hatchling의 기본 메타데이터 2.5를 Twine 6.2가 받지 못하여 wheel 메타데이터를 2.4로 고정하고 재검증하였다.
- 최초 설치형 실행 검증에서 `CREATE_NO_WINDOW`로 시작한 자식의 표준 출력이 전달되지 않아 접속 주소를 읽지 못하였다. CLI가 출력·오류 스트림을 명시적으로 전달하도록 수정하였다. 남은 해당 테스트 실행부를 정리하고 새 wheel의 전체 설치형 통합 검증을 통과하였다.
- 네모 걷기 샘플의 `samples/01-movement/고양이.py`는 검사 시 0바이트였다. 초기 좌표는 맞지만 이동·말풍선·완료 출력이 없어 샘플 검증이 실패하였다. 사용자 편집일 수 있어 보존하고 복원 여부를 질문하였으며, 이후 사용자의 복원 요청에 따라 아래 후속 검증을 수행하였다. 이 파일은 wheel의 기본 프로젝트 원본이 아니므로 설치형 기본 프로젝트와 구분한다.

## 네모 걷기 샘플 복원 후속 검증

같은 날짜에 사용자의 요청으로 `samples/01-movement/고양이.py`를 복원하였다. 이전 샘플 검증의 임시 복사본에서 원래 코드를 확인하였다. 네 번의 160단위 이동과 90도 왼쪽 회전, 시작·완료 말풍선, 완료 위치 출력을 복원하였으며 다른 학생 파일은 변경하지 않았다.

`node --test tests/Samples.test.mjs`는 5/5 통과이다. 실제 샘플을 임시 폴더에 복사하여 네모 이동 경로, 초기 위치·방향 복귀, 완료 말풍선·로그와 나머지 네 샘플을 확인하였다. `node --test --test-name-pattern=01-movement tests/Editor.test.mjs`는 1/1 통과이며 복원한 코드의 명령 인식 오류가 없었다. UTF-8·LF와 `git diff --check`도 확인하였다.

최초 전체 검증에서 실패했던 한 항목은 해소되었다. 이번 복원에서는 위 샘플·편집기 검사만 다시 실행하였으며 전체 155개 테스트를 재실행한 것은 아니다. 샘플은 wheel 입력이 아니므로 기존 wheel을 다시 빌드하지 않았다.

## 미검증 범위와 후속 단계

PyPI 계정이 없어 공개 업로드와 공개 저장소에서의 `pip install blackpy`는 수행하지 않았다. PyPI의 해당 프로젝트 JSON 조회는 404였지만 이름 등록 가능 여부는 실제 업로드 성공으로 확정한다.

Python 3.10·다른 Python 버전의 실제 실행, SDK가 설치되지 않은 별도 PC, 실제 VS Code·Pylance UI, 이번 변경 후의 브라우저 시각 검사는 수행하지 않았다. 새 테스트는 실제 HTTP·WebSocket 연결을 사용하며 브라우저 자동 열기는 생략하였다. 학생 HTML·교사용 자료는 수정하지 않았다. 해당 자료에는 설치 절차와 프로젝트 폴더를 여는 안내의 반영이 필요하다.

stub은 런타임의 AST 변환 전체를 표현하지 않는다. 함수 안의 `크기 += 0.1` 같은 상태 갱신에는 일반 Python의 대입 전 지역 변수 경고가 남을 수 있다. 이 제한과 `크기_바꾸기` 명령 대안은 Usage에 기록하였다.
