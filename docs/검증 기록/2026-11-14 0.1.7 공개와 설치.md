# BlackPy 0.1.7 공개와 설치

## 공개 결과

소스 커밋은 `f0d1f84d98ca34befce0feeb92b48f83c84705db`이다. 기존 미커밋 기능과 회전 충돌·트리거를 포함하여 main에 푸시하였다.

- [공개 전 검증 실행](https://github.com/dove-creative/blackpy/actions/runs/43483118826)은 전체 검증·wheel 업로드에 성공하였고 PyPI 작업은 생략하였다.
- 같은 커밋의 중복 push 실행은 수동 검증과 중복되어 취소하였다.
- [공개 실행](https://github.com/dove-creative/blackpy/actions/runs/43483833158)은 전체 검증 후 Trusted Publishing으로 [PyPI 0.1.7](https://pypi.org/project/blackpy/0.1.7/)을 공개하였다. 장기 API 토큰은 사용하지 않았다.

공개 실행의 Actions 산출물, PyPI 메타데이터와 PyPI에서 내려받은 wheel의 SHA-256이 일치하였다.

```text
blackpy-0.1.7-py3-none-win_amd64.whl
75be6fce634774a8144b220f572e5dd63952f46dfa3f11fab6b5953f5d5d321e
```

## 설치·실행

터미널에서 실제 사용하는 uv 관리 CPython 3.13.18의 사용자 site-packages와 VS Code 기본 인터프리터인 pygame 가상환경을 확인한 뒤, 검증한 공개 wheel로 두 환경의 0.1.6을 0.1.7로 갱신하였다. uv 관리 Python 자체를 수정하지 않고 사용자 영역을 갱신하였다.

별도의 새 가상환경에는 `pip install --no-cache-dir --index-url https://pypi.org/simple blackpy==0.1.7`로 설치하였다. 업로드 직후 simple 색인에 이전 버전만 보여 첫 시도는 실패하였고, 색인 반영 후 재시도에서 정상 설치되었다.

세 환경 모두 다음 두 경로를 실제로 실행하여 총 6회 통과하였다.

1. `python -m blackpy run <임시 프로젝트> --no-browser --port 0`
2. `python <임시 프로젝트>/고양이.py --no-browser --port 0`

각 실행은 새 프로젝트 생성, 트리거 편집기 인자 안내, 기본 고체 벽 차단, 보급품 트리거 통과·접촉, 후진, 90도 회전, 마지막 웹 연결 종료 시 프로세스 종료를 확인하였다. 학생 파일은 실행 전후 바뀌지 않았다. 설치된 pygame 환경의 명령 진입점도 `BlackPy 0.1.7`을 반환하였다. 터미널에서는 PATH에 의존하지 않는 `python -m blackpy`를 검증하였다.

VS Code 화면 조작 자체는 수행하지 않았으며, 설정된 인터프리터의 직접 실행과 기존 편집기 자동 검증으로 확인하였다. 별도 SDK 없는 장비와 실제 화면 표시 FPS는 이번 검증 범위가 아니다.
