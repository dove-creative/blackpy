# BlackPy 저장소 분리 검증 기록

이 문서는 2026-11-07에 수행한 독립 저장소 전환과 배포 검증 결과이다.

## 변경 범위

- BlackPy를 공개 MIT 저장소로 분리하고 UniEngine·BlackboxSystem·BlackThunder Conventions를 고정 커밋의 서브모듈로 연결하였다.
- BlackboxSystem을 직접 NuGet 참조하여 UniEngine과 같은 패키지 버전을 사용하도록 하였다.
- 배포 기본값을 `artifacts/blackpy`로 변경하고 통합·배포 테스트의 외부 경로 의존을 제거하였다.
- BlackPy와 라이브러리 고지, 실제 동봉하는 .NET·ASP.NET 런타임 팩 버전의 라이선스·제3자 고지를 배포에 포함하였다.
- README와 개요·구현·사용·개발·테스트 문서를 BT Conventions에 따라 구분하였다.

실행 순서는 C#·Python 단위 테스트, Publish, 통합 테스트, 기본·놀이 배포 테스트이다. 상세 명령은 [테스트 계획](../Testing.md)에 있다. 생성된 TRX와 배포 JSON 보고서는 `artifacts/test-results`에 보관하고 Git에서 제외하였다.

## 실행 중 확인한 사항

초기 샌드박스 실행에서는 NuGet 취약성 정보 연결 경고가 발생하고 로컬 통신을 사용하는 검증이 대기하였다. 해당 검증 프로세스를 종료한 뒤 일반 개발 환경에서 테스트를 실행하였다. 후속 배포용 복원은 경고 없이 성공하였다.

C# 단위 테스트 복원과 배포 검증을 동시에 실행하면 공유 `obj/project.assets.json`이 일반 타깃으로 갱신되어 `-SkipRestore` 배포에서 `NETSDK1047`이 발생하였다. 배포용 복원을 다시 수행한 뒤 두 배포 테스트를 순서대로 실행하여 통과하였다. 테스트 계획에도 이 실행 순서를 반영하였다.

## 확인하지 않은 범위

SDK가 없는 별도 컴퓨터에서는 실행하지 않았다. PATH와 `DOTNET_ROOT`를 제한한 개발 컴퓨터에서 실제 동봉 `coreclr.dll`의 로딩을 확인하였다. 이번 분리에서 새 화면 시각 검사는 수행하지 않았으며 README 미리보기는 기존 실행 화면이다.

별도 클론 빌드는 동일 개발 컴퓨터의 기존 NuGet 캐시를 사용하였다. 외부 사용자 계정이나 빈 NuGet 캐시에서 모든 패키지를 다운로드하는 검증은 수행하지 않았다.

UniEngine 소스 저장소는 비공개 상태를 유지한다. 일반 빌드는 저장소에 포함된 패키지를 사용하고, 원본 소스 초기화와 소스 커밋 검증은 해당 저장소 접근 권한이 있는 개발자에게만 해당한다.
