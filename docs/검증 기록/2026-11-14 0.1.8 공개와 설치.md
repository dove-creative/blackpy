# BlackPy 0.1.8 공개와 설치

## 공개 결과

소스 커밋은 `5839475c17539f873b79fc95f04f5b7f5fbfcbcc`이다. 변경과 로컬 검증은 [0.1.8 기본값·키 누름·말하기·뒤집기 검증 기록](2026-11-14%200.1.8%20기본값·키%20누름·말하기·뒤집기.md)에 있다.

- main push로 시작된 검증 실행은 같은 커밋의 공개 실행과 중복되어 취소하였다.
- [공개 실행](https://github.com/dove-creative/blackpy/actions/runs/43559339161)은 `expected_version=0.1.8`, `publish=true`로 실행하였다. Windows 전체 검증과 wheel 빌드를 통과한 뒤 Trusted Publishing으로 [PyPI 0.1.8](https://pypi.org/project/blackpy/0.1.8/)을 공개하였다. 장기 API 토큰은 사용하지 않았다.

PyPI 메타데이터와 PyPI에서 내려받은 wheel의 SHA-256이 일치하였다.

```text
blackpy-0.1.8-py3-none-win_amd64.whl
cd34c56b972d7639ee50af5de49ec33895bb00b65228cda50c1d294dbf7cb3ba
```

공개 작업은 검증 작업이 올린 `blackpy-wheel` 산출물(ID 14099812556)을 예상 digest `sha256:1be6504a237e2e609a89960800e02adac16b01d5cc562946702c945cace3a797`와 대조하여 내려받았다. 업로드 로그에 기록된 wheel의 SHA-256도 위 값과 같다. 산출물 zip을 이 PC로 직접 내려받는 대조는 저장소 응답 속도(초당 약 28KB) 때문에 중단하고 실행 로그로 확인하였다. 업로드에는 PEP 740 디지털 증명이 함께 생성되었다.

로컬에서 빌드한 wheel은 빌드 시각이 달라 해시가 다르며 공개 파일의 근거로 사용하지 않았다.

## 설치·실행

PyPI에서 내려받아 해시를 확인한 wheel로 이 PC의 세 환경을 갱신하였다.

| Python 환경 | 설치 위치 | 이전 버전 |
| --- | --- | --- |
| 터미널 기본 uv 관리 CPython 3.13.18 | 사용자 site-packages | 0.1.7 |
| VS Code 기본 인터프리터 pygame 가상환경 | 해당 가상환경 | 0.1.7 |
| Anaconda CPython 3.10.9 | 사용자 site-packages | 0.1.6 |

uv 관리 Python은 PEP 668 외부 관리 환경이라 일반 `--user` 설치를 거절하였다. 사용자 승인을 받아 `--user --break-system-packages`로 사용자 site-packages만 교체하였고 uv가 관리하는 Python 본체는 변경하지 않았다. 이 Python은 PATH의 첫 `python`이므로 수업 폴더의 `시작.bat`이 사용한다.

세 환경에서 `python -m blackpy --version`이 `BlackPy 0.1.8`을 반환하였다. 설치된 실행부·웹 무대·편집기 안내 파일 7개가 소스와 같았고 자동 실행 훅이 설치되어 있었다. 임시 프로젝트의 학생 파일을 각 Python으로 직접 실행하여 다음을 확인하였다.

- 웹 무대가 `favicon.svg` 탭 아이콘을 연결하고 제공한다.
- `앞으로()`로 100 이동한 뒤 `뒤집기("가로")`로 방향이 180도가 되고, 다시 `앞으로()`로 출발점에 돌아온다.
- 기본 말하기가 표시된 뒤 1초 기다렸다가 지워지고 다음 줄로 진행한다.
- `키_누름`이 실행되고, `키_누름_중`의 `앞으로(1)`이 뒤집힌 방향으로 이동한다.
- 마지막 웹 연결을 닫으면 실행부가 종료 코드 0으로 끝난다.

결과는 로컬 `artifacts/test-results/local-install-0.1.8.json`에 있다. VS Code 화면 조작과 실제 브라우저 탭 표시는 수행하지 않았다.
