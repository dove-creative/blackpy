# 무대 전역변수 검증 기록

## 변경 내용

BlackPy 0.1.14에서 함수 밖의 변수를 배경과 모든 캐릭터가 공유하도록 변경하였다. 함수 안의 global 대입·증감·삭제는 같은 공유 공간에 반영하며, 함수의 지역 변수·매개변수·클로저와 nonlocal은 기존 Python 범위를 유지한다. 함수 정의·import·명령 대상·캐릭터 상태는 객체별로 유지한다.

초기화 순서는 배경과 설정의 캐릭터 순서이다. 중복 대입은 나중 값이 적용되고, 새 실행은 빈 공유 공간에서 다시 초기화한다. 사용 안내에 배경에서 한 번 초기화하는 점수 예제와 일반 Python 및 편집기 분석과의 차이를 추가하였다.

## 환경과 결과

Windows x64, .NET SDK 10.0.404, Python 3.13.18, Node.js 24.15.0에서 검사하였다.

자동 테스트는 합계 417개이며 별도의 배포 시나리오도 통과하였다. 설치 대상은 터미널의 실제 실행 경로와 VS Code 사용자 설정의 기본 인터프리터를 확인하여 선택하였다. 로컬 wheel의 크기는 49,025,229바이트이며 SHA-256은 `1bbb5c2c94abbc4b4ad35c61f822875c8fe773bc1a45a713025df7638eb4ef73`이다.

초기 Python 검사는 샌드박스 안에서 asyncio의 로컬 socketpair 생성에 멈추어 중단하고 샌드박스 밖에서 실행하였다. 텍스트 입력 테스트의 종료 조건은 이전 객체별 namespace.get 대신 공유 공간을 조회하도록 수정하였다. 추가한 통합 테스트는 첫 실행에서 왼쪽 버튼 필드가 누락되었고, 다음 실행에서는 초기화 전에 입력을 보냈다. 버튼 필드와 시작 이벤트의 0점 표시 대기를 추가한 뒤 이벤트 전체 13개가 통과하였다. 제품 구현을 우회하거나 검증을 생략하지 않았다.

첫 .NET 테스트에서 NuGet 취약성 서비스 조회 실패에 따른 NU1900 경고가 있었으나 테스트는 통과하였다. 이후 배포와 wheel 빌드의 복원은 완료하였다.

## 확인 범위와 한계

다른 파일의 변수 읽기·쓰기, 지역 변수 격리, 객체별 함수와 상태, 공유 리스트, 주석·다중 대입, 내포식·람다·클로저, 원래 오류 위치와 초기화 순서를 Python 테스트로 확인하였다. 실제 HTTP·WebSocket·Python 실행부에서 한 객체를 세 번 누른 뒤 다른 객체에 3이 표시되고, 다시 시작하면 0이 표시되는 것을 확인하였다.

Pyright의 기존 명령 안내 검사는 통과하였으나 다른 파일의 공유 변수 이름을 편집기에 자동 등록하는 기능은 추가하지 않았다. 실제 VS Code·Pylance 화면 검사, 전체 수업 화면 검사, 별도의 SDK 없는 장비와 Python 3.10 실행은 수행하지 않았다. 수업 자료의 파일 단위 전역변수 설명에는 새 규칙에 따른 후속 정리가 필요하다.

터미널의 `blackpy` 단독 명령은 현재 PATH에서 찾을 수 없었으며 `python -m blackpy`의 0.1.14 실행을 확인하였다. PATH 설정은 변경하지 않았다. 로컬 설치만 수행하였고 PyPI 공개는 하지 않았다.

검증 로그는 `artifacts/shared-globals-*.log`, 설치본 점수 검사는 `artifacts/verify-installed-shared-globals.py`에 있다. 배포 검사는 개발 컴퓨터에서 수행한 결과이다.
