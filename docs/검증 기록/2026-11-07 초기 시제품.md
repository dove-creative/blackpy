# BlackPy 초기 시제품 검증

이 문서는 독립 저장소 분리 전 초기 시제품의 검증 기록이다. 아래 날짜·수치·환경·한계와 임시 보고서 경로는 당시 기준이며, 독립 저장소 분리 후의 검증 결과와 구분한다.

검증일: 2026-11-07. Windows x64 개발 컴퓨터, .NET SDK 10.0.403, Python 3.10.9, Node.js 24.15.0, Chrome에서 수행했다.

## 실행 검증

이동 단위 테스트 **18/18**, 실제 배포본의 Python·HTTP·WebSocket 통합 테스트 **18/18**을 통과했다.

- 전후진, 음수·0 거리, 좌우 90도·360도 회전, 방향을 유지하는 `goto`, 무대 밖 이동, 사각형 왕복을 확인했다.
- 동작 완료 전에는 다음 Python 출력이 나오지 않는 것을 관찰했다.
- 저장 후 재실행, 중복 시작 409, 이동 중 중지·직접 재시작, 새 실행이 진행 중일 때 이전 실행 식별자의 명령 거절을 확인했다.
- API를 호출하지 않는 무한 반복과 줄바꿈 없는 연속 출력을 중지했다.
- 문법 오류·일반 예외의 `main.py` 파일·줄, 한국어 출력, stdout·stderr 대량 출력, 최근 1,000줄 제한, 없는 `main.py`, `input()`의 EOFError를 확인했다.
- 웹 연결 두 개 중 하나를 닫으면 실행이 유지되고 마지막 연결을 닫으면 중지됐다. 재접속은 위치·출력·실행 식별자를 복원했다.
- Python 부모가 먼저 끝나도 남은 자식을 종료하고 출력 수집을 마쳤다. 호스트 강제 종료 후 부모·자식 프로세스가 모두 사라지는 것도 확인했다.
- 잘못된 `PYTHON_EXE` 이후 PATH Python으로 대체했고, 모든 검색 경로에서 찾지 못하면 안내 후 서버를 열지 않고 종료했다.
- 한글·공백 경로의 실제 Python venv를 만들고 PATH를 비운 상태에서 인터프리터 탐색·25단위 이동·한국어 출력을 확인했다. 상속 인코딩을 CP949로 바꾼 회귀 사례는 수정 전 실패, UTF-8 적용 후 통과했다.

초기 샌드박스에서는 NuGet 네트워크 및 테스트 호스트의 로컬 연결이 제한되어 실행하지 못했다. 필요한 복원과 테스트를 허용된 환경에서 다시 수행한 결과가 위 통과 수치이다.

## 실제 화면 확인

시제품의 시작 버튼으로 사각형을 실행해 `완료!` 출력을 확인했다. 다시 시작 뒤 이동 중 중지하면 마지막 위치가 남았으며 새로고침 후에도 해당 위치와 중지 상태가 복원됐다. 실제 웹 무대는 4:3 비율로 표시되고 가로 넘침과 브라우저 JavaScript 오류가 없었다. 학생의 기존 `main.py`는 화면 검증에서 수정하지 않았다.

## 배포 검증과 한계

한글과 공백이 있는 TEMP 경로에 실습 폴더 전체를 복사했다. 다른 작업 폴더에서 복사한 BAT를 그대로 실행하고 웹·인증 WebSocket 연결, 기본 사각형, 복사본 코드 수정·저장 후 37단위 이동을 확인했다.

PATH에서 `dotnet`을 찾지 못하게 하고 `DOTNET_ROOT` 계열을 빈 디렉터리로 지정했다. 실행 중 프로세스 모듈을 읽어 복사본의 `_runtime/coreclr.dll`이 로드됐음을 확인했다. .NET·ASP.NET 런타임 파일과 `runtimeconfig.json`의 `includedFrameworks`도 확인했다. 별도 배포 위치에서 Publish를 두 번 실행해 기존 `main.py`의 SHA-256이 유지됐다. 원본 실습 파일은 변경되지 않았다.

검증용 호스트와 자식 프로세스는 종료했다.

SDK가 설치되지 않은 별도 컴퓨터에서의 실제 실행은 아직 검증하지 않았다. `py -3`만 있는 환경도 실제 실행 검증 대상이 아니었다. 수업 화면 검증은 대표 본책·익힘책을 대상으로 했으며 전체 페이지의 시각 검사는 아니다. 기존 `문제 생성 규칙.md`의 4·10·14행 끝 공백은 작업 전에도 있던 것으로 보존했다.

## blackpy 이름 변경 검증

화면 제목을 `blackpy`로, C# 네임스페이스·프로젝트·실행 파일을 `BlackThunder.BlackPy`로 변경했다. BAT·배포 스크립트·테스트·문서 경로도 맞췄다.

이름 변경 뒤 단위 테스트 18/18과 통합 테스트 18/18을 다시 통과했다. 복사한 실습 폴더의 실제 BAT 실행, 저장 코드 재실행, 자체 포함 런타임 로딩, 반복 배포 시 기존 코드 보존도 재검증했다. 원본 `main.py`의 변경 전후 SHA-256이 일치한다. 새 배포 폴더에는 이전 이름의 실행 파일이 없으며, Python 학생 API와 연결 프로토콜은 유지했다.

## 첫 다섯 놀이 단원 검증

검증일: 2026-11-07. 조사 보고서의 첫 다섯 사례인 자동차 이동·댄스 파티·달리기 경주·농구공 드리블·으스스한 숲을 실행 가능한 BlackPy 단원으로 추가했다. 이 절은 위의 초기 시제품 검증과 별도로 이번에 실행한 결과이다.

| 검사 | 결과 |
| --- | --- |
| C# 전체 테스트 | 29/29 통과: 기존 이동 18개와 장면 11개 |
| Python 놀이 명령 테스트 | 10/10 통과: 시간·좌표·회전·경주·공동 1등·드리블·입력 경계 |
| Python 3.10.9 전체 통합 테스트 | 25/25 통과: 기존 실행 제어와 신규 다섯 놀이 포함 |
| Python 3.13.18 추가 통합 테스트 | 7/7 통과: 다섯 놀이, 중지·재시작, 마지막 웹 연결 종료 |
| 학생 HTML·교사용 Markdown·예제·배포 코드 | 다섯 단원 모두 대응, 예제와 배포 main.py 바이트 일치 |
| 자료의 상대 링크 | 학생·교사용 15개 파일의 82개 링크 정상 |
| 기존 학생 main.py | 작업 전후 SHA-256 일치 |
| 반복 배포 | 기본 실습과 다섯 놀이의 수정한 main.py를 2회 배포 후에도 보존 |

실제 Python 실행에서 중간 프레임을 수집했다. 경주의 두 캐릭터가 서로 다른 속도로 동시에 이동하고 먼저 도착한 캐릭터가 도착선에서 기다리는 것, 드리블에서 친구와 공이 함께 이동하며 공이 초기 높이로 돌아오는 것, 춤과 박쥐의 한 바퀴 회전을 확인했다. 장면은 중지·완료 후 유지되고 새 실행에서는 초기화된다. 이전 실행 프레임, 잘못된 연결 토큰, 잘못된 크기는 거절됐다. 64개 캐릭터의 긴 한글 라벨이 서버 요청 크기 제한 안에 들어가는지도 확인했다.

실습 폴더 전체를 한글·공백 TEMP 경로로 복사한 뒤 다른 작업 폴더에서 다섯 `시작.bat`을 각각 실행했다. 복사본 자동차의 `420`을 `210`으로 고쳐 저장·재시작한 뒤 최종 x=-50을 확인했다. 원본 학생 파일은 그대로였다. 배포 검증은 `ActivityDeployment.test.mjs`로 재현하며 결과는 `.codex_tmp/blackpy-first-five/deployment.json`에 남긴다.

Chrome에서 다섯 무대의 실제 그림과 완료 출력을 확인했다. 댄스 실행 중 중지·다시 시작, 자동차·드리블 수업의 코드 복사와 체크·완료 표시의 새로고침 초기화를 확인했다. 본문은 28px, 코드는 22px이며 검사한 화면에 가로 넘침이 없었다. 다섯 무대의 브라우저 JavaScript 오류는 0개였다. 경주 화면은 `.codex_tmp/blackpy-first-five/race-preview.png`에 보관했다. 검증용 탭과 임시 서버는 종료했다.

이번 실행에서도 NU1900 경고로 온라인 NuGet 취약성 조회는 완료되지 않았으나 빌드·배포·테스트는 통과했다. SDK가 없는 별도 컴퓨터와 모바일 브라우저는 검증하지 않았다. 그림은 자체 벡터 도형이고 소리·클릭·키보드·접촉 판정·점수 기능은 이번 범위에 포함하지 않는다.

## 배포 경로 검증

2026-11-07에 초기 실행 예제의 배포 경로를 정리하였다. 이동 대상 31개 파일이 새 위치에 존재하고, 경로를 바꾼 BAT를 제외한 실습 파일 16개의 SHA-256이 일치하였다. 다섯 학생 main.py와 다섯 blackpy.py도 그대로 보존하였다. 자료 15개의 상대 링크 82개와 다섯 단원의 코드 대응을 검사하였다.

최초 배포 검사에서는 LF 배치파일의 코드페이지 전환 뒤 명령 일부가 잘려 실행에 실패하였다. BAT를 UTF-8 무BOM·CRLF로 맞추고 해당 경로의 .gitattributes 규칙을 추가하였다.

수정 후 Python 3.13.18에서 새 구조의 배포 검사를 통과하였다. 한글·공백 경로의 복사본에서 다른 작업 폴더를 기준으로 다섯 BAT를 각각 실행하였으며, 자동차 코드 수정·저장·재시작 결과도 확인하였다. 두 차례 Publish 후 기존 main.py가 그대로였고 이전 배포 경로가 다시 생기지 않았다. 기존 기본 실습 배포 테스트는 전체 재실행하지 않고 변경된 경로의 구문만 확인하였다.
