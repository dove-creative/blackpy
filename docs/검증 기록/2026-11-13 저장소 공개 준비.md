# BlackPy 저장소 공개 준비 검증 기록

## 변경 범위

공개 문서와 과거 커밋의 문서에서 외부 교육 자료의 연결·보관 위치 안내를 제거하였다. 초기 시제품의 검증 기록은 실행부 검증 결과와 당시 환경·한계를 유지하고 외부 자료의 보관 구조 설명을 정리하였다. AGENTS에는 공개 문서에 외부 교육 자료의 저장소 링크와 보관 위치를 기재하지 않는 기준을 추가하였다.

사용자의 승인에 따라 과거 이력까지 정리하였다. 원본 이력은 Git에서 제외한 artifacts/public-review의 bundle에 보관하였다. 실행 코드·NuGet 패키지·프로젝트 설정·이미지·서브모듈은 각 원본 커밋과 동일한지 비교하였다. 별도로 진행한 0.1.2 릴리스와 기존 샘플·스토리보드 변경은 보존하였다.

## 환경과 점검

2026-11-13 Windows x64 개발 컴퓨터에서 Git, GitHub CLI, Python 3.13으로 확인하였다.

| 검사 | 결과 |
| --- | --- |
| 원본 이력의 텍스트 검사 | 최초 9개 커밋의 고유 blob 243개에서 주요 토큰·개인키·이메일·전화번호 패턴 미검출이다. 외부 교육 자료 참조는 확인하여 제거 대상으로 분류하였다. |
| 중간 이력 수정본 | 0.1.2 소스를 포함한 10개 커밋의 고유 blob 254개에서 같은 패턴과 제거 대상 참조가 남지 않았음을 확인하였다. |
| 최종 이력 | 0.1.2 공개 기록까지 포함한 원본 12개 커밋을 정리하고 이번 검증 기록을 별도 커밋으로 추가하였다. 전체 이력의 텍스트 검사와 문서 이외 파일·서브모듈 비교 결과는 prepared-history-check.json에 보관하였다. |
| 실행 구성 보존 | 각 원본·수정 커밋의 Markdown 이외 파일과 서브모듈 항목이 일치하였다. |
| Actions 로그 | 0.1.2 공개 실행까지 13건, 로그 총 1,284,831바이트에서 검사한 패턴과 외부 교육 자료 참조가 미검출이다. 취소된 실행에서 시작되지 않은 공개 작업은 실행 단계와 로그가 없음을 확인하였다. |
| 동봉 NuGet | 패키지 2개의 내부 파일에서 주요 토큰·개인키 형식과 제거 대상 링크가 미검출이다. 소스 파일과 PDB는 동봉하지 않았다. |
| README 미리보기 | 이미지를 직접 확인하였으며 외부 자료의 보관 위치는 표시되어 있지 않았다. |
| 문서 링크 | 새 검증 기록을 포함한 문서 40개의 로컬 Markdown 링크 75개가 모두 유효하였다. |
| 파일 형식 | 검사한 Markdown은 UTF-8 무BOM·LF·마지막 개행을 유지하였다. 변경 문서의 git diff --check가 통과하였다. |
| Git 객체 | 정리된 이력의 git fsck --no-dangling이 통과하였다. |

검사 명세와 결과는 artifacts/public-review의 JSON에 보관하였다. 토큰·개인키 형식과 이메일·전화번호 등의 패턴 검사는 모든 형태의 비밀값·개인정보 부재를 보증하는 검사는 아니다.

## 공개 결과

정리된 main을 원격에 반영한 뒤 GitHub API에서 visibility=public과 private=false를 확인하였다. 공개 설정 확인 시 원격에는 정리된 main 하나만 존재하였고 검토한 커밋과 일치하였다. 결과는 artifacts/public-review/publication-result.json에 보관하였다.

로컬 main과 origin/main도 정리된 이력으로 맞추었다. 동기화 전후 작업 파일 174개의 SHA-256이 모두 같았다. 기존 샘플 코드의 마지막 빈 행 변경과 스토리보드 원본은 미커밋 상태로 보존하였다. 비교 결과는 artifacts/public-review/worktree-preservation.json에 있다.

## 검증 경계

이번 변경은 문서와 Git 이력 정리이다. 실행 동작과 빌드 입력의 변경이 없으므로 이 작업을 위한 제품 전체 테스트는 다시 실행하지 않았다. 별도 0.1.2 릴리스의 테스트와 공개 결과는 해당 릴리스 기록으로 구분한다.

이력 재작성은 기본 브랜치에서 열람하는 커밋과 문서를 정리하는 작업이다. 이미 발급된 PyPI 출처 증명이나 다른 복사본은 수정하지 않는다. GitHub의 옛 커밋 캐시는 이력 재작성만으로 삭제가 보장되지 않으며 별도의 처리 대상이다. [GitHub 이력 정리 안내](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)
