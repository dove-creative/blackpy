# BlackPy 캐릭터별 스크립트 전환 검증 기록

이 문서는 2026-11-12에 수행한 캐릭터별 Python 코드, 프레임 이벤트, 한글 명령 목록과 새 배포 형식의 검증 결과이다.

## 변경 범위

- 단일 학생 파일과 15개 놀이 예제를 배경·캐릭터별 파일 및 프로젝트 설정으로 교체하였다.
- 일반 이벤트의 순차 완료와 유지 이벤트의 프레임별 호출·시간 기반 이동, 상태 직접 대입, 방송과 접촉 전환을 구현하였다.
- 웹에 대상 선택, 명령 코드 행 복사, 캐릭터 말풍선과 실행 전 미리보기를 추가하였다.
- 기존 학생 파일·설정을 보존하는 새 배포를 만들었다. 기존 작업 중이던 예제와 이전 배포·통합 테스트는 삭제 전에 로컬 `.cache/refactor-backup-2026-11-12`에 복사하였다. 이 백업은 배포물과 Git 추적 대상이 아니다.

## 환경과 결과

Windows x64, .NET SDK 10.0.404, Python 3.13.18, Node.js 24.15.0, PowerShell 7 환경에서 검증하였다. 소스의 C# 언어 버전은 9이며 실행 대상은 .NET 10이다.

| 검증 | 결과 |
| --- | --- |
| 로컬 의존성 검사 | UniEngine·BlackboxSystem 두 패키지의 참조·해시 검사 통과 |
| C# 단위 테스트 | 46개 통과, 실패·건너뜀 없음 |
| Python 단위 테스트 | 39개 통과 |
| 웹 입력·무대·팔레트 테스트 | 20개 통과 |
| 실제 배포본 통합·이벤트 테스트 | 16개 통과 |
| Windows x64 자체 포함 배포 | `artifacts/blackpy/실습` 생성 성공 |
| 배포 검증 | 8개 확인 항목 통과, 보고서 `passed: true` |
| 파일 형식 | 변경한 텍스트의 UTF-8·LF, BAT의 무BOM·CRLF, 최종 개행 확인 |
| 변경 공백 검사 | `git diff --check` 통과 |

자동 단위·통합 테스트 합계는 121개이다. 배포 확인 항목과 실제 화면 검사는 이 수치에 포함하지 않았다.

실행 명령은 다음과 같다. 네트워크 복원과 로컬 소켓을 사용하는 검사는 해당 접근이 허용된 환경에서 실행하였다.

```powershell
$env:NUGET_PACKAGES = Join-Path (Get-Location) '.cache/nuget'
./scripts/Verify-Dependencies.ps1
dotnet test tests/BlackThunder.BlackPy.Tests.csproj -c Release --nologo
python -m unittest discover -s tests -p 'test_*.py'
dotnet restore src/BlackThunder.BlackPy/BlackThunder.BlackPy.csproj -r win-x64 --nologo
./scripts/Publish.ps1 -SkipRestore
node --test tests/WebInput.test.mjs tests/WebStage.test.mjs tests/WebPalette.test.mjs
node --test tests/Integration.test.mjs tests/EventIntegration.test.mjs
node tests/Deployment.test.mjs
```

## 확인한 동작

- 일반 이동·회전 완료 뒤 다음 명령 실행, 서로 다른 객체의 병행 실행, 같은 객체의 이동 변화량 합산이다.
- 유지 이동의 프레임 시간 적용과 30·60·120FPS 결과 일치, 속도 배율, 절대 상태 설정과 보조 함수의 실행 문맥이다.
- 키별 일회성 재입력 무시, 유지 이벤트의 매 프레임 새 호출, 입력 종료 후 이미 시작한 호출 완료이다.
- 누른 순간의 클릭 대상 유지, 빈 곳의 배경 클릭, 초점 상실 시 키·마우스 해제이다.
- 접촉 시작·유지·종료 목록, 숨김에 따른 접촉 해제, 방송 신호별 재진입 구분이다.
- 프로젝트의 전체 파일 고정, 재시작 후 변경 반영, 고정된 원래 파일·줄·오류 문장 보존이다.
- 상태 대입·증감, 객체별 상태 격리, 무한 반복 중 다른 이벤트 진행과 중지, 활성 호출 상한 오류이다.
- 출력 상한, 잘못된 프로젝트·비유한 값 거절, 마지막 브라우저 종료 시 실행 중지, Python이 만든 자식 프로세스 정리이다.

배포 검사는 한글·공백이 있는 임시 폴더에 배포본을 복사하고 다른 작업 폴더에서 BAT를 실행하였다. 자식 환경의 PATH에서 dotnet을 제외하고 DOTNET_ROOT를 빈 폴더로 지정한 뒤, 실제 프로세스가 복사된 `_runtime/coreclr.dll`을 읽었음을 확인하였다. 기본 프로젝트 실행, 캐릭터 코드 수정 후 재시작, 두 차례 재배포 후 모든 학생 코드·설정의 바이트 보존, 구형 목적지 거절을 확인하였다. 보고서는 `artifacts/test-results/deployment-verification.json`이다.

## 실제 화면 검사

- 앱 내 브라우저에서 좁은 화면의 세로 배치와 데스크톱 화면의 무대·로그 및 오른쪽 명령 목록을 확인하였다.
- 실제 시작·다시 시작·중지, 캐릭터 말풍선과 안내 문구를 확인하였다.
- 방향키를 약 0.5초 누른 뒤 고양이의 x가 -160에서 약 -102로 이동하는 것을 확인하였다.
- 배경을 선택했을 때 움직임 항목이 사라지고 배경 파일명과 전용 안내가 표시되었다.
- 키 유지 이벤트의 코드 행을 클릭한 뒤 임시 확인 페이지에 붙여 넣어 `def 키_클릭_중(누른_키):`와 들여쓴 `pass`가 복사됨을 확인하였다. VS Code 자체의 붙여넣기 검사는 하지 않았다.
- 검사 중 브라우저 오류·경고 로그는 없었다. 새 실제 화면은 [미리보기](../images/preview.jpg)에 보관하였다.
- 임시 확인 페이지와 브라우저 탭, 테스트 실행부를 정리하였다. 마지막 프로세스 조회에서 남아 있는 BlackPy 실행부는 없었다.

## 발견한 문제와 한계

- 첫 NuGet 복원은 제한된 실행 환경의 DNS 오류로 실패하였다. 네트워크 접근이 허용된 환경에서 복원·검증을 완료하였다.
- 제한된 실행 환경에서는 Windows asyncio의 루프백 소켓 초기화가 대기하였다. 대기 프로세스를 종료하고 로컬 통신이 허용된 환경에서 Python 테스트를 수행하였다.
- 첫 배포본 통합 검사는 `runpy` 실행 시 지원 모듈 폴더가 검색 경로에 없어서 16개 중 14개가 실패하였다. 실행기 검색 경로를 수정한 뒤 16개 모두 통과하였다. 검증한 배포본의 네 Python 지원 모듈은 원본과 SHA-256이 일치하였다.
- 초기화 중 시간 소요 명령 대기, 예약 상태 이름의 특수 대입 구문, 극단 속도의 0시간 이동과 넓은 좌표 차이의 방향 계산을 보완하고 회귀 테스트를 수행하였다.
- 별도의 SDK 없는 컴퓨터와 Python 3.10에서는 실행하지 않았다. 지원 하한은 유지하지만 이번 실제 Python 검증 버전은 3.13.18이다.
- 외부 학생 HTML과 교안은 수정·재배포하지 않았다. 기존 파일 구성과 영어 API를 사용하는 자료는 새 형식에 맞게 개편해야 한다.
