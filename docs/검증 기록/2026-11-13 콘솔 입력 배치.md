# 콘솔 입력 배치 검증 기록

## 변경 범위

실행기 제목 아래 문구를 Designed by dove_creative로 변경하였다. input의 질문·입력칸을 콘솔 출력 다음에 배치하고 객체 이름을 붙인 질문자 표시를 제거하였다. Enter 또는 입력 보내기 버튼으로 한 줄을 제출한다.

Python 런타임은 유효한 답을 접수하면 질문과 답을 한 번 출력한 뒤 대기 호출을 재개한다. 중복·이전 실행 답은 출력하지 않으며 빈 답과 앞뒤 공백은 그대로 유지한다. 빈 질문에 빈 답을 제출한 출력도 콘솔에서 한 줄 높이를 차지한다. 질문이 유지되는 동안 초안과 초점을 보존하고 새 질문에서만 콘솔을 아래로 스크롤한다. 질문과 답은 기존 실행 출력의 보관 한계를 따르며 브라우저 저장소에는 기록하지 않는다.

## 실행 환경과 산출물

2026-11-13 KST의 Windows x64 개발 컴퓨터에서 .NET SDK 10.0.404, Python 3.13.18, Node.js 24.15.0, PowerShell 7.6.9, Pyright 1.1.414를 사용하였다.

폴더 배포본은 artifacts/blackpy이다. 최종 wheel은 artifacts/wheels/blackpy-0.1.1-py3-none-win_amd64.whl이며 크기는 48,945,850바이트이다. SHA-256은 `e75d7ece9aae693e4de22b131a1d8c5569c4a6be00c44925f078db8f6cd26e88`이다. 새 임시 배포본으로 wheel을 빌드하고 Twine strict 검사를 통과하였다.

[Testing](../Testing.md)의 전체 검증을 수행하였다. .NET 테스트와 배포·wheel 빌드는 순차 실행하였다.

테스트 러너 합계는 226/226이다. 빈 출력 행 높이를 보완한 뒤 웹 검사와 배포·wheel 빌드를 다시 수행하고 최종 wheel의 설치형 검사 26개를 재실행하였다. 출력은 artifacts/test-results의 console-runtime.log, console-deployment.log, console-publish.log, console-wheel.log, console-packaging.log에 있다.

초기 Python 단위 검사에서는 새 출력이 Windows 기본 cp949 스트림으로 전달되어 유니코드 오류가 발생하였다. 테스트의 표준출력을 StringIO로 수집하도록 수정한 뒤 통과하였다. 제품 실행부는 UTF-8로 통신한다. 화면 확인용 실행기를 켜 둔 재배포 시도는 DLL 잠금으로 실패하였으며, 해당 임시 프로세스를 종료한 뒤 재빌드하였다. 화면 확인 보조 Node 프로세스는 종료 중 libuv assertion을 보고하였고 이후 해당 보조 프로세스와 배포 실행기가 남지 않았음을 확인하였다. 제품의 자동 종료 검사는 별도로 통과하였다.

## 브라우저 확인

최종 폴더 배포본과 임시 학생 파일을 in-app 브라우저에 연결하여 확인하였다.

- 제목 아래의 Designed by dove_creative와 콘솔 내부의 한 줄 입력 배치이다.
- 한글 답을 Enter로 제출한 뒤 질문·답·후속 print 출력의 순서이다.
- 다음 질문에 120을 입력하고 입력 보내기 버튼으로 제출한 뒤 int 변환과 캐릭터의 x=-100에서 x=20 이동이다.
- 빈 질문에 빈 답을 Enter로 제출한 뒤 22.5px 높이의 빈 출력 행과 정상 완료이다.
- 다시 시작할 때 첫 질문과 빈 입력칸 복원, 입력 대기 중 중지할 때 입력칸 숨김이다.
- 폭 480 화면에서 입력칸·버튼의 겹침과 가로 넘침이 없는 배치이다. 임시 화면 크기 설정은 확인 뒤 해제하였다.

확인 화면은 [콘솔 입력 화면](../../artifacts/test-results/console-input.jpg)에 있다. 한글 문자열은 자동 입력으로 확인하였으며 실제 운영체제 IME 조합·확정 키 입력은 별도로 검증하지 않았다.

## 수업 자료 영향과 한계

수업 자료에서는 input의 질문·답을 실행기 콘솔에서 확인하는 흐름으로 설명하면 된다. input의 문자열 반환과 int·float 변환 순서는 유지되며 별도 프레임워크 코드는 필요하지 않다. 이번 화면 변경으로 외부 수업 자료는 수정하지 않았다.

Python 3.10 실제 실행, SDK가 없는 별도 PC, 실제 VS Code 버튼 조작은 이번 검증에 포함하지 않았다. 로컬 wheel을 임시 환경에서 검증하였으며 커밋·푸시·GitHub Actions 실행·PyPI 공개와 기본 Python 환경의 패키지 교체는 수행하지 않았다.
