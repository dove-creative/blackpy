# Python 파일 직접 실행 검증 기록

## 변경 범위

BlackPy 0.1.1 wheel에 Python 시작 연결을 추가하였다. 설치된 Python으로 프로젝트 바로 아래의 `.py` 파일을 실행하면 해당 파일의 코드를 먼저 실행하지 않고 프로젝트 전체의 웹 무대를 연다. 학생 파일에 실행 코드나 import를 추가하지 않는다. 직접 실행한 파일이 객체로 등록되지 않았어도 무대는 열리지만 그 파일이 새 캐릭터로 등록되지는 않는다.

대상은 같은 폴더의 `project.json`에 문자열인 `background.file`과 배열인 `actors`가 있는 경우이다. 일반 폴더, 하위 폴더, `.pyw`, `-c`·`-m`·표준 입력 실행은 자동 연결하지 않는다. `BLACKPY_AUTO_RUN=0`으로 연결을 해제할 수 있다. 미설치·제거 후에는 Python 본래의 파일 실행으로 돌아간다. 기존 `시작.pyw`의 미설치 안내와 구분한다.

시작 연결은 설치형 패키지와 내부 실행기의 동명 모듈을 분리한다. 학생 런타임도 프로젝트 경로를 잠시 제외한 뒤 내부 모듈을 준비하며 학생 코드 실행 전에 프로젝트 경로를 다시 제공한다. 학생의 보조 모듈 import는 유지한다. 학생 Python 파일·프로젝트 설정·편집기 안내 파일은 수정하지 않았다.

## 실행 환경과 입력

2026-11-12 Windows x64 개발 컴퓨터에서 Python 3.13.18, Node.js 24.15.0, .NET SDK 10.0.404, PowerShell 7.6.9, Pyright 1.1.414를 사용하였다.

최종 로컬 wheel은 `artifacts/wheels/blackpy-0.1.1-py3-none-win_amd64.whl`이며 크기는 48,809,105바이트이다. SHA-256은 `67bcd3df05f4560c80e4c97f9605834ce0a75197eeac0f759cab33979e096ca0`이다. 새 임시 배포본에서 빌드하였으며 설치 검증은 임시 가상환경에서만 수행하였다. 기본 Python 환경에는 설치하지 않았다.

테스트 러너 합계는 180/180 통과이다. 로그는 `artifacts/test-results/direct-run-*.log`에 있다.

직접 실행 검사는 다른 작업 폴더에서 한글·공백 경로의 배경, 캐릭터, 미등록 Python 파일, 문법이 잘못된 동명 `blackpy.py`를 각각 선택하였다. 모두 같은 프로젝트의 등록된 객체 전체를 실행하였다. `json.py`·`argparse.py`가 프로젝트에 있어도 내부 모듈로 잘못 읽지 않았으며 학생 보조 모듈의 import와 출력은 유지하였다. 등록된 캐릭터 파일의 문법 오류는 무대 로그에 원래 파일 이름과 함께 표시되었다.

미설치, 자동 연결 해제, 일반·다른 형식·손상된 프로젝트 설정, 하위 폴더와 다른 Python 진입 방식의 동작을 확인하였다. 마지막 WebSocket 연결 종료 후 직접 실행 프로세스도 종료되었다. 제거 후 시작 연결 파일이 없어지고 원래 Python 실행으로 돌아왔으며 학생 파일은 그대로 보존되었다. 모든 검증 후 BlackPy 실행부와 Python runner의 잔여 프로세스는 0개이다.

## 영향과 미검증 범위

학생 HTML·교안·배포 래퍼는 읽기 전용으로 영향을 확인했으며 수정하지 않았다. 기존 샘플의 학생 `.py`, `project.json`, `__builtins__.pyi`와 새 프로젝트 원본에도 변경이 없다.

VS Code의 실제 실행 버튼 클릭, 탐색기의 파일 연결과 실제 브라우저 화면은 이번 검사에서 조작하지 않았다. VS Code가 사용하는 `python 파일.py` 형태를 임시 가상환경의 실제 프로세스·HTTP·WebSocket으로 검증하였다. Python 3.10 실제 실행, 사용자 사이트 설치와 SDK가 없는 별도 PC는 검증하지 않았다.

소스 버전과 공개 워크플로 입력을 0.1.1로 준비하였으나 커밋·푸시·GitHub Actions 실행·PyPI 공개는 수행하지 않았다. 확인 시점의 PyPI 공개 버전은 0.1.0이며 이번 기능은 로컬 0.1.1 wheel에만 포함되어 있다.
