# 샘플 설치 전제 검증 기록

## 변경 범위

샘플의 실행 전제를 해당 Python 환경에 설치된 BlackPy로 통일하였다. `scripts/SampleLauncher.pyw`와 샘플별 동일한 `시작.pyw`는 설치 정보를 확인한 뒤 설치형 명령으로 자기 프로젝트를 실행한다. 미설치 상태에서는 설치 안내 후 종료하며 저장소의 실행부, 현재 폴더의 동명 모듈이나 `PYTHONPATH`를 대체 실행 경로로 사용하지 않는다.

더블클릭 진입점은 창 없는 Python 실행을 사용하고 오류는 안내창에 표시한다. `Debug.bat`은 같은 실행기를 콘솔 모드로 호출한다. 설치·실행에는 같은 Python을 사용하며 패키지를 자동 설치하지 않는다. 사용자 사이트를 포함한 정상 설치 경로는 유지한다.

기존 샘플 `시작.exe` 5개는 생성된 진입점임을 확인한 뒤 `.cache/retired-sample-launchers`로 이동하였다. `Publish.ps1`의 샘플 EXE 생성과 관련 ignore 규칙을 제거하였다. 폴더 배포본의 `실습/시작.exe`는 기존 방식으로 생성한다. 학생의 `.py`, `project.json`, `__builtins__.pyi`는 변경하지 않았다.

샘플 진입점 테스트가 wheel을 설치하므로 문서와 GitHub Actions의 실행 순서를 wheel 빌드 뒤로 옮겼다. 공개된 패키지의 API와 실행 코드는 변경하지 않았으며 이번 작업에서 새 PyPI 배포는 수행하지 않았다.

## 실행 환경

2026-11-12 Windows x64 개발 환경에서 Python 3.13.18, Node.js 24.15.0, .NET SDK 10.0.404, PowerShell 7.6.9, Pyright 1.1.414를 사용하였다.

일반 통합·샘플 동작·배포 검사는 이번에 만든 폴더 배포본으로 수행하였다. 설치형 패키지 검사는 새로 빌드한 로컬 wheel을 사용하였다. 샘플 진입점 검사는 실제 공개된 BlackPy 0.1.0의 wheel을 별도 임시 가상환경에 설치하여 수행하였다.

테스트 러너 집계는 160/160 통과이다. 로그는 `artifacts/test-results/sample-installed-*.log`에 보관하였다.

미설치 가상환경에서는 로컬 배포 실행부가 실제로 연결되어 있어도 실행을 거절하였다. `PYTHONPATH`에 개발용 지원 모듈을 지정하고 샘플 폴더에 동명 모듈을 추가한 조건에서도 우회 실행되지 않았다. 설치 후 샘플 5개가 각자의 설정과 시작 이벤트를 실행하였고 마지막 브라우저 연결 종료 후 실행기도 종료되었다. 제거 후에는 다시 설치 안내를 표시하며 학생 코드·설정·편집기 안내를 보존하였다.

현재 기본 Python에서도 `python samples/01-movement/시작.pyw --console --no-browser`가 설치 안내와 종료 코드 1을 반환하였다. 기본 Python에는 테스트를 위해 BlackPy를 설치하지 않았다. 재배포 후 샘플 EXE는 0개, 새 `시작.pyw`는 5개이며 검증 종료 후 남은 BlackPy 실행부와 Python runner 프로세스는 0개이다.

## 영향과 미검증 범위

외부 자료의 Markdown·HTML·PowerShell에서 새 샘플 경로와 `blackpy run`의 참조를 검색하였으나 일치 항목이 없었다. 배포 래퍼는 별도 목적지의 폴더 배포를 호출하므로 이번 샘플 진입점 변경으로 호출 방법이 바뀌지 않는다. 외부 학생 HTML·교안과 BlackPy 참조는 수정하지 않았다.

GUI의 안내창 호출과 콘솔 숨김 옵션은 대역으로 확인하였다. 탐색기의 실제 `.pyw` 파일 연결·더블클릭 화면, Python 3.10 실제 실행, 사용자 사이트에 직접 설치하는 경우와 SDK가 없는 별도 PC는 검증하지 않았다. 변경한 GitHub Actions는 정적 검사만 수행하였으며 이번 변경의 원격 실행은 수행하지 않았다.
