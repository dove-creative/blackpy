# UniEngine·컨벤션 갱신 검증

## 변경

UniEngine을 main 커밋 `688b41d57d67e67ec7b4f01a6cd3c60ba902b7d2`으로, 공통 컨벤션을 `cc73310b8727df10ec8af2f8bbd7d596b0dbf4e5`로 갱신하였다. 소스 서브모듈과 고정 커밋의 Git 아카이브로 생성한 NuGet, import 스크립트, 직접 패키지 참조, 출처 매니페스트와 개발 문서를 함께 갱신하였다. 검증을 마친 뒤 이전 `0.1.0-main.a933cbd` 패키지를 제거하였다.

BlackPy 버전은 0.1.8이며 BlackboxSystem은 0.2.0을 유지한다. 실행부에는 UniEngine API 직접 호출이 없어 새 수학·공간 API에 대응하는 소비 코드 변경은 없었다.

| 항목 | 값 |
| --- | --- |
| UniEngine 패키지 | `UniEngine.0.1.0-main.688b41d.nupkg` |
| 패키지 SHA-256 | `9D1B4D09BBD43AAB57E3F2E631FB1343BBD4B5728964549FD63472A8A00268F8` |
| UniEngine DLL SHA-256 | `65CFA4A4B1EDB961EFDE2D0FB97B719DA0886069F8A5B1398B953D0164681F4D` |
| wheel | `blackpy-0.1.8-py3-none-win_amd64.whl` |
| wheel SHA-256 | `3F48C52B6E78F4F451B01181BDF857121458374F3FBB8D8CDB5810B40B0C56C2` |

패키지 내부 DLL, 일반·win-x64 빌드 출력, 기본 폴더 배포본과 wheel 내부 DLL의 해시가 모두 일치하였다.

## 후행 콤마 적용

`COM-COMMA-01`과 `COM-COMMA-02`를 프로젝트가 소유한 C#·Python·JavaScript 코드와 테스트에 적용하였다. 지원하는 여러 줄 나열에 후행 콤마를 붙이고 한 줄의 선택적 후행 콤마는 생략하는 기준이다. 문법이나 의미에 필요한 콤마는 유지하며, 서브모듈·외부 코드·캐시·생성된 배포본은 직접 일괄 수정하지 않았다. 현재 문서의 Python 예시도 확인하였으며 변경할 대상이 없었다.

| 언어 | 확인한 소스 파일 | 변경한 파일 | 추가한 콤마 | 제거한 콤마 |
| --- | --- | --- | --- | --- |
| C# | 23 | 16 | 62 | 0 |
| Python·stub | 45 | 16 | 74 | 0 |
| JavaScript | 23 | 23 | 443 | 0 |

C#은 Roslyn 구문 구조로 초기화·열거형·switch 식 등 허용 구문만 수정하였다. 조건부 컴파일 조합도 확인하였고, 콤마 이외의 토큰과 주석이 유지되었다. 메서드 인자·매개변수·튜플처럼 후행 콤마를 허용하지 않는 구문은 변경하지 않았다.

Python은 구문 트리와 콤마를 제외한 토큰·주석의 일치를 확인하고 Python 3.10 문법으로도 파싱하였다. JavaScript는 Acorn 구문 트리·토큰·주석을 비교하였다. 의미가 달라지는 한 요소 튜플과 배열의 빈 요소는 보존하였다. 세 언어 모두 다시 적용했을 때 추가 수정 대상이 없었다. 수정한 코드의 줄 끝은 LF이다.

로컬 검증 로그와 구문 비교 결과는 `.cache/main-688b41d-validation`에 보관한다. `01-import.log`부터 `10-packaging.log`까지 패키지 생성과 전체 검증의 결과를 순서대로 기록하였다.

## 범위

프레임 성능 측정, 실제 브라우저 화면·IME·VS Code 버튼 조작, 별도 SDK 미설치 컴퓨터 실행, PyPI 공개와 사용자 환경의 설치는 수행하지 않았다. 전체 검증과 의존성 갱신은 로컬 배포본·wheel 및 Git 저장소를 대상으로 하였다.
