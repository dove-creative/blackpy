# BlackPy 창 없는 실행과 자동 종료 검증 기록

이 문서는 2026-11-12에 수행한 GUI 진입점과 브라우저 연결에 따른 자동 종료의 검증 결과이다.

## 변경 범위

- 배포본과 샘플 5개에 콘솔을 할당하지 않는 `시작.exe`를 생성한다. 관리 코드와 런타임은 기존 공통 실행부에 두고 상대경로로 찾는다.
- 실행 파일과 같은 폴더의 프로젝트를 기본으로 사용하며 `--project`로 명시한 경로를 우선한다.
- 마지막 웹 연결이 닫히면 Python 실행과 자식을 중지하고 3초 뒤 호스트도 종료한다. 다른 탭이 있거나 유예 중 재연결하면 호스트를 유지한다.
- 자동 브라우저 실행에서 첫 연결은 최대 60초 기다리며, 브라우저 열기 실패는 오류로 종료한다. 콘솔이 없는 일반 실행의 준비 오류는 안내 창으로 표시한다.
- 사용 안내는 `시작.exe`를 기본 진입점으로 설명하며 기존 BAT는 진단용으로 유지한다.

## 환경과 자동 검사

Windows x64, .NET SDK 10.0.404, Python 3.13.18, Node.js 24.15.0, PowerShell 7.6.9 환경이다.

| 검증 | 실제 결과 |
| --- | --- |
| `Verify-Dependencies.ps1` | 로컬 패키지 2개의 참조·해시 확인 통과 |
| C# 전체 테스트 | 53개 통과 |
| Python 전체 테스트 | 39개 통과 |
| 웹 전체 테스트 | 20개 통과 |
| 통합·샘플·GUI 진입점 | 29개 통과: 기존 통합 16개, 수명 3개, 샘플 5개, GUI 진입점 5개이다. |
| `Publish.ps1` | 기본 배포본과 샘플 5개의 GUI 실행 파일 생성 성공 |
| `node tests/Deployment.test.mjs` | 9개 확인 항목 통과, 학생 설정 원본 보존 |

위 자동 테스트는 총 141개 통과하였다. 수명 단위 검사는 첫 연결 제한과 재연결 유예를 가상 시각으로 확인한다. 실제 통합 검사는 마지막 연결 해제 뒤 정상 종료, Python 자식 정리, 여러 탭과 새로고침 재연결을 확인한다.

샘플 GUI 진입점 검사는 한글·공백이 있는 임시 폴더에 프로젝트와 실행 파일을 복사하고 별도의 작업 폴더에서 실행하였다. GUI subsystem 값 2와 해당 프로젝트 선택을 확인하고 실행 중 마지막 웹 연결을 닫아 정상 종료를 확인하였다. 테스트는 학생 원본 파일을 수정하지 않는다.

배포 검사는 복사된 `시작.exe`를 다른 작업 폴더에서 실행하고 자식 환경의 PATH에서 dotnet을 제외하였다. 실제로 복사된 `_runtime/coreclr.dll`을 사용함을 확인하였다. 기본 프로젝트 실행·저장 후 재시작·마지막 연결 후 정상 종료와, 두 차례 재배포 시 학생 Python·설정의 바이트 보존을 확인하였다. 구형 목적지 거절도 통과하였다. 결과는 `artifacts/test-results/deployment-verification.json`에 있다.

최종 런처 생성은 SDK의 MSBuild 태스크로 수행하였다. 이 방식으로 재생성한 샘플 GUI 실행 파일 5개의 실행·종료 검사를 다시 통과하였다.

## 실제 브라우저 확인

임시 복사한 배포본의 `시작.exe --no-browser`를 실행하고 앱 내 브라우저로 연결하였다. 시작 버튼으로 실행한 뒤 새로고침하여 연결과 마지막 장면이 유지되고 학생 실행은 중지된 상태임을 확인하였다. 다시 실행하고 실제 탭을 닫자 GUI 호스트가 종료 코드 0으로 종료되었다. 결과는 `artifacts/test-results/gui-browser.json`에 있다.

## 검사 중 보완과 한계

첫 통합 실행에서는 장면을 기다리지 않고 출력 로그만 확인한 직후 연결을 닫아, 새로고침 검사의 장면 조회가 한 번 실패하였다. 첫 장면이 게시된 것을 확인한 뒤 닫도록 테스트를 보완하고 전체 통합 29개를 다시 통과하였다.

런처 생성 도구의 호환성 검토 중 SDK의 net472 라이브러리를 PowerShell에 직접 로드한 진단이 완료되지 않아 중단하였다. 최종 구현은 SDK의 `dotnet msbuild` 프로세스로 생성하며, 관련 진단 프로세스를 종료하였다.

별도의 SDK 없는 학생 장비, Python 3.10과 이전 PowerShell 7 버전은 실제로 실행하지 않았다. 기본 브라우저 종류별 화면과 준비 오류의 네이티브 안내 창은 별도로 검사하지 않았다. 자동 브라우저의 첫 연결 60초 제한은 수명 단위 테스트로 검증하였다.

## 진단용 배치 이름과 화면 안내 정리

같은 날짜의 후속 작업에서 배치 원본·샘플 5개·현재 배포본의 이름을 `Debug.bat`으로 바꾸고 배포 스크립트와 현재 사용 문서를 맞췄다. 일반 실행 파일은 `시작.exe`이다. 웹의 수동 저장 단축키 안내를 제거하고, 코드를 바꾼 뒤 다시 시작하라는 안내를 유지하였다. 토큰 없이 접근했을 때도 일반 실행 파일을 안내한다.

`Publish.ps1 -SkipRestore` 빌드·배포와 기존 웹 테스트 20개를 새로 실행하여 통과하였다. 배치 7개의 이전 파일명 부재와 UTF-8 무BOM·CRLF를 확인하고, 배포된 HTML·CSS·JavaScript가 원본과 일치하며 저장 단축키 문구가 없는지 검사하였다. 이 이름·문구 변경에 대한 전체 런타임 테스트와 브라우저 화면 검사는 추가로 실행하지 않았다.
