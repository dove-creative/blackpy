# 독립 시뮬레이션 검증 기록

## 변경 범위

C# 세션이 단조 시계로 물리·명령 이동·장면 게시를 최대 60Hz로 진행한다. Python의 요청 횟수나 요청에 담긴 시간으로 물리를 진행하지 않는다. Windows 정밀 대기 타이머와 요청 신호를 함께 기다리며, 바쁜 대기와 시스템 전체 타이머 해상도 변경을 사용하지 않는다.

Box2D.NET의 1/120초 고정 간격과 각 계산의 4개 세부 단계는 유지한다. C#의 한 갱신에서 소비하는 시간은 최대 0.1초이며 고정 계산은 최대 12회이다. 이를 넘는 지연과 놓친 외부 갱신은 연속 재생하지 않는다.

Python은 일반 이동의 총변위·회전·시간을 한 번 등록하고, 완료 응답의 실제 위치를 반영한 뒤 다음 문장을 실행한다. 유지 이동은 입력별 초당 이동·회전 상태로 등록한다. 새 호출의 상태가 이전 호출을 대체하며, C#은 입력 해제 때 해당 상태를 즉시 지운다. 해제·재누름 뒤 이전 호출에서 늦게 도착한 이동은 적용하지 않는다. Python 함수 자체의 대기와 나머지 문장은 계속 실행한다.

입력의 현재 상태와 Python에 전달할 전환 기록을 구분한다. 접촉 시작·종료는 순서 번호와 수신 확인으로 보존하며, 한 응답에 여러 접촉 주기가 담겨도 각 전환을 전달한다. 초기 장면 등록 뒤 시작 함수를 실행한다. 중지·오류·완료·재시작은 이전 물리 세계와 명령을 정리한다.

## 환경과 산출물

2026-11-13 KST의 Windows x64 개발 컴퓨터에서 .NET SDK 10.0.404, Python 3.13.18, Node.js 24.15.0, PowerShell 7.6.9, Pyright 1.1.414를 사용하였다.

폴더 배포본은 artifacts/simulation-validation이다. 최종 wheel은 새 임시 배포 폴더에서 빌드한 artifacts/wheels/blackpy-0.1.1-py3-none-win_amd64.whl이며 크기는 48,975,379바이트이다. SHA-256은 `e8a3b1936d7c8318c769c7f64e056c5498fff17b96b3aa952e26560a48010a88`이다. Twine strict 검사를 통과하였다.

## 자동화 검증

[Testing](../Testing.md)의 전체 검증을 수행하였다. .NET 테스트, Publish와 wheel 빌드는 순차로 실행하였다. 최종 통합 검증은 빌드와 분리했고, 성능 측정은 다른 테스트가 끝난 뒤 실행하였다.

| 검증 | 결과 |
| --- | --- |
| 의존성 | 로컬 NuGet 패키지 2개의 해시·직접 참조 확인 통과이다. |
| C# | 130/130 통과이며 빌드 경고·오류는 없다. |
| Python | 88/88 통과이다. |
| 통합·이벤트·물리·독립 시뮬레이션·텍스트 입력·브라우저 수명·샘플 | 최종 전체 실행에서 42/42 통과이다. |
| 웹 | 33/33 통과이다. |
| 설치형·편집기·샘플 진입점·직접 실행 | 최종 wheel에서 29/29 통과이다. |
| 배포 | 동봉 런타임·라이선스·학생 파일 보존·한글 경로·종료 등 별도 10개 항목 통과이다. |

테스트 러너 합계는 322/322이다. 새 독립 시뮬레이션 통합 테스트 5개는 다음 동작을 실제 실행부로 확인한다.

- Python의 native time.sleep 중에도 중력·일반 이동·새 장면 전달이 진행된다.
- 등록한 유지 이동이 Python 정체 중에도 계속되고, 키 해제는 즉시 반영된다. 재누름 후 이전 호출의 이동은 거부된다.
- Python 명령 교환을 약 20Hz로 늦춰도 C#이 그 사이에 새 위치와 장면을 생성한다.
- Python 정체 동안 발생한 접촉 시작·종료가 복귀 후 순서대로 전달된다.
- 명령 요청 폭주가 별도의 시간 진행을 만들지 않는다. 중복 순서 번호는 명령을 재실행하지 않으며, 이전 실행과 기존 물리 시간 진행 API를 차단한다.

단위 테스트는 완료 뒤 위치 조회, 응답 대기 중 새 절대 위치·방향 보존, 입력 세대·최신 호출의 우선순위, 누적 입력과 최신 상태의 분리, 반복 접촉 전환과 대기 중인 함수, 초기 장면과 시작 호출의 순서도 검증한다.

주요 결과는 artifacts/test-results의 csharp-independent-simulation-20261113.log, simulation-python.log, simulation-integration-final.log, simulation-installed-final.log, simulation-deployment.log에 있다.

## 실제 갱신률

06-physics의 임시 복사본에서 점프와 초기 위치 복귀를 반복하였다. 3초의 준비 시간을 제외하고 각 조건을 20초 측정하였다.

```powershell
$env:BLACKPY_DISTRIBUTION = Join-Path (Get-Location) 'artifacts/simulation-validation'
node scripts/Measure-FrameRate.mjs 20
node scripts/Measure-FrameRate.mjs 20 slow
```

slow 조건은 Python의 각 명령 교환에 50ms 대기를 넣는다. Python 수치는 스크립트와 명령 교환의 처리율이며, 성공 기준인 58.5~61.5Hz는 WebSocket 장면 전달에만 적용한다.

| 측정 | 일반 실행 | Python 지연 실행 |
| --- | --- | --- |
| Python 명령 교환 | 60.000Hz | 19.133Hz |
| WebSocket 장면 전달 | 60.000Hz | 60.000Hz |
| 장면 평균 간격 | 16.667ms | 16.667ms |
| 장면 중앙값 간격 | 16.660ms | 16.671ms |
| 장면 95백분위 간격 | 17.117ms | 17.138ms |
| 장면 최대 간격 | 18.237ms | 17.573ms |
| 장면 33.333ms 초과 | 0/1199 | 0/1199 |

두 조건 모두 장면 전달 목표를 충족하였다. Python 명령 교환이 19.133Hz로 느려져도 C# 장면 전달은 60Hz를 유지하였다. Python이 새로운 판단이나 명령을 내리는 시점까지 C#이 대신 실행하는 것은 아니다.

원자료는 [일반 실행 결과](../../artifacts/test-results/frame-rate-1794502222061/report.json)와 [Python 지연 실행 결과](../../artifacts/test-results/frame-rate-1794502265341/report.json)이다. 브라우저 canvas의 실제 화면 표시 FPS를 계측한 결과는 아니다.

## 수정 중 확인한 문제

최신 입력 상태가 아직 전달하지 않은 눌림·해제 이벤트를 건너뛰게 하는 문제와, 일반 이벤트의 중복 실행 방지가 누적 접촉 전환을 버리는 문제를 발견하여 수정하였다. 두 경우 모두 회귀 테스트를 추가하였다. 시작 함수의 출력이 첫 C# 장면 등록보다 빨리 전달되어 클릭 대상이 배경으로 판정될 수 있는 초기화 순서도 수정하고 검증하였다.

새 통합 테스트의 초기 검사에는 부동소수점 좌표의 정확한 문자열 비교, input API의 응답 형식, 중복 순서 번호의 멱등 처리에 대한 기대 오류가 있었다. 실제 계약에 맞게 수정하였으며 이동량·시간·독립 갱신의 판정 기준은 완화하지 않았다.

중간에 wheel 빌드와 통합 테스트를 함께 실행했을 때 브라우저 수명 테스트의 자식 프로세스 종료 대기와 Integration 테스트 파일의 비정상 종료가 각각 한 번 발생하였다. 해당 두 실패는 격리 실행과 빌드를 분리한 최종 전체 42개 실행에서 재현되지 않았다. PID 재사용이나 환경 부하가 원인인지는 확정하지 않았다.

## 확인 범위

일반 학생 명령과 샘플 파일의 이름·인자 사용법은 유지하였다. 교사용·학생용 자료에서 새 유지 이벤트 이름과 60프레임 설명을 읽기 전용으로 검색하였다. 확인된 60프레임 설명은 별도 Pygame 수업의 clock.tick이며 이번 BlackPy 변경의 대상이 아니다. 외부 수업 자료와 도구 복사본은 수정하지 않았다.

수정 코드·문서·설정의 UTF-8 무BOM·LF·끝 개행을 확인하였다. 전체 diff 공백 검사에는 기존 samples/02-keyboard/고양이.py의 마지막 빈 행 한 건이 남아 있으며 수정하지 않았다.

성능 수치는 이 개발 컴퓨터의 두 객체 물리 예제에 대한 결과이다. Python 3.10, 다른 장비·브라우저의 실제 화면 표시 FPS, SDK가 없는 별도 PC는 검증하지 않았다. 검증용 복사본과 임시 가상환경을 사용하였으며 기본 Python 환경의 패키지를 교체하지 않았다. 커밋·푸시·GitHub Actions 실행·PyPI 공개는 수행하지 않았다.

최종 artifacts/simulation-validation 실행부로 원본 06-physics 예제를 브라우저에 다시 열었다. 로컬 API에서 running, 활성 장면과 객체 2개를 확인했으며 사용자의 직접 확인을 위해 실행해 두었다.
